# 整板布线流水线（#307）

**目标**：细间距 4 层板也能在分钟级得到结果：要么布通，要么给出每个未通网络布不通的原因；写回后经保存、重载和原生 DRC 验证。实现细节见[详细稿](pcb-route-pipeline-design-detail.md)。

## 现状

#307 要的大部分零件已经有了，缺的是把它们串起来的两步，以及失败时的原因：

| 步骤 | 现有能力 | 缺口 |
|---|---|---|
| 布线前检查 | `pcb routability`：列出没有出线也没有过孔位的焊盘 | 无 |
| 关键网 | `pcb route-critical`：电源与差分对先布并锁定 | 无 |
| 扇出 | `pcb escape-plan` 联合预留细间距器件的出线路径与过孔 | **只是规划，不能写成铜** |
| 其余信号 | `pcb autoroute`：官方路由器，以原生作业方式运行，可取消 | 无 |
| 写回 | `pcb plan-apply`：批量写入并按网络、层对账 | 无 |
| 未通原因 | 原生 DRC 只说哪些网络没连上 | **不知道堵在哪个焊盘、被什么挡住** |

## 方案（建议）

沿用 2026-10-17 的决定：信号主体由**官方路由器**布，不接 Freerouting（GPL、需要 Java）。本期只补两个缺口：

1. **`pcb fanout`**：把 `escape-plan` 通过的预留路径和过孔写成真实铜，复用 `plan-apply` 的写入与对账，写完锁定，让官方路由器从扇出端点接着布。
2. **`pcb route-diagnose`**：读一份新的 dump 和同一状态的 DRC 结果，对每个未通网络，用与 `routability` 相同的几何找出是哪个焊盘被困、被哪些对象挡住；焊盘本身都能出线时，说明阻断发生在焊盘之间的通道上。它是只读命令。

Skill 中写明固定顺序：检查 → 关键网 → 扇出 → 官方自动布线 → 诊断 → 保存、重载、DRC。每一步都输出布通数、未通清单和新增违例。

## 不做什么

- 本期不自研整板多层求解器。离线整板求解留在社区求解包 `pcbsolve` 的路线上（目前支持两层），等它支持四层后再接入同一流水线。
- 不改变官方路由器本身的行为，也不替用户放宽规则。

## 已确认（2026-11-26）

- 采用“官方路由器 + 补扇出和诊断”，暂不自研整板求解器。
- 扇出写入后默认锁定，防止官方路由器拆掉。

## 实施顺序

1. `pcb route-diagnose`（只读，风险最低，马上能用来解释现有的布线失败）。
2. `pcb fanout`（写入，复用 `plan-apply`）。
3. 更新 Skill 流程，在 ceshi 上用 0.4 mm 间距 QFN 板现场走一遍。
