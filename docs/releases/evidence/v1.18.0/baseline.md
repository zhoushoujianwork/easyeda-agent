# v1.18.0 定向修复验收基准

## 本版用户范围决定

2026-11-14，用户在确认 v1.17.0 后的修复改动了连接器运行时、必须升中版本后，选择发布 v1.18.0；
随后在明确获知完整点灯板 E2E 尚未执行、并对比"schema 3 定向修复范围"与"先跑完整点灯板 E2E"两个选项后，
选择 schema 3 定向修复范围。本版因此采用 `cli-fixes` 有限范围：全量自动回归；#299 在真实 EasyEDA 中构造触发条件并验证修复后回读；
#303 的现场复现、修复后回读和旧版负对照。完整设计 E2E 延期至 follow-up，此决定只绑定 v1.18.0。
报告中的 `pass` 只表示本版明确定义的用例通过，不表示电路、制造、硬件或完整设计验收通过。

#299 复现步骤中"把电阻向左拖 10 个单位"必须在界面完成（API 拒绝零长度导线，API 移动器件不带动导线）。
用户在本轮明确要求由 Agent 直接通过 GUI 完成这一步，作为仓库"禁止 GUI 编辑工程"规则的一次性例外；
#303 需要的 `mil` 规则存储同理：API 写入规则会被宿主统一存回 `mm`，只能在设计规则对话框中切换单位。
两处 GUI 操作只用于在一次性测试工程 `ceshi` 中制造前置条件；GUI 制造前置条件后的判定均以 CLI 显式保存、重载后的新回读为准。

## 原始需求与起点

完整设计的默认原始需求仍为 `docs/test-case-esp32-blink.md` 第一节，文件 SHA256 为
`21bd4682110228de90ee71a8402680eb7668dad5bb7557d44d368d5ff4cd118c`。本轮未执行该流程，
没有输入预制 BOM、UUID、网表或坐标答案。

现场起点：一次性测试工程 `ceshi`，原有原理图页 P1（遗留未连线器件，本轮未改动）与空 PCB1，
规则为系统预设 `JLCPCB Capability(Two Layers Board)`（`mm` 存储）。本轮新建原理图页 P2
（`8fb55bd61d0986a9`）用于 #299；#303 将原理图导入 PCB1（30 个器件）后，由 CLI 写入生成板级
`自定义配置13`，再在对话框中把单位切为 `mil`。外部问题报告的原始数值（6 / 10 / 20 mil 板、
235.6 / 393.7 误读值、过孔 12.0078 / 24.0158 / 393.7008 mil）只作为对照目标，不作为工具输入。

## 通过阈值与不豁免项

自动回归不得有失败，跳过的平台限定测试保留跳过事实。#299：零长度导线存在、带网名导线互不相交时，
`wire-contact` 必须为 0，且同一图元自身折线不得报异网接触。#303：同一套规则以 `mm` 或 `mil` 存储时，
`route-short` 读到的 mil 值必须一致，并能规划出走线；旧版在同一块板上必须复现误读，才算负对照成立。
正式发布仍须完成 `release-check`、`release-build`、资产校验、安装冒烟、远端资产核验，以及用户对具体版本的批准。
本范围决定不允许伪造现场回读、放宽设计判据或删除失败记录。
