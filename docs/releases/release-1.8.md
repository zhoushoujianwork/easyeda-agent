## 实施顺序

1. 记录上述范围决定及已有基础证据；三项保持 open，按 issue 后续修复和复测。
2. 固定实际 CLI、daemon、连接器候选，核对当前目标及双页完整基线，补运行本次完整流程实际依赖的缺口。
3. 由无历史设计上下文的执行 Agent，只从 `esp32MiniRequire.md` 第一节开始选型、规划、
   原理图执行与检查，再完成 PCB 同步、四层配置和布局；不提供旧 BOM、网表或候选布局。
4. 展示通过连续两轮回读检查的 PCB 布局，由用户确认后进行整板布线、铺铜和 DRC。
5. 保存、真实重载、fresh 回读与独立复核全部通过后，统一正式版本，执行 `release-check`、
   `release-build`，再按[发布流程](../release-workflow.md)创建发布和核验远端资产。

复用测试工程与叠层 A 的既有选择继续有效，不重复确认；它不代替尚未生成的 PCB 布局确认。
本次还需覆盖局部修改、写前拒绝和中断恢复，不能只跑一个顺利创建的正向流程。
