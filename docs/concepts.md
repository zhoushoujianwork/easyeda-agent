## Agent 协作入口与文档归属

**公开设计 Skill** 指 `.agents/skills/easyeda-agent/`，是可独立安装的 EDA 工作流与知识包。
**仓库协作 Skill** 指 `.agents/skills/easyeda-repo-*/`，通过安装链接定位源码 checkout，
用于跨项目查询和维护；它依赖仓库内容，不属于公开设计包，也不增加 EDA 执行通道。
**兼容入口** 只引用同一规范源：`CLAUDE.md → AGENTS.md`、`.claude → .agents`；
公开设计 Skill 与仓库协作 Skill 都是 `.agents/skills/` 下的真实目录；根目录不再保留第二个
Skill 目录。源码位置不改变发布包内的 `easyeda-agent/` 根目录或用户级安装位置。

**文档归属** 指每类信息有一个维护位置：协作规则、操作知识、架构理由、验证证据分别维护，
入口和索引只路由到该位置。历史报告说明特定版本发生过什么，不覆盖当前规范，也不证明新版
已验证。具体导航与归属表见 [文档索引](README.md)，设计理由见 [Agent 协作设计](agent-collaboration.md)。

## 原理图架构基准入口

[数据驱动架构基准](../.agents/skills/easyeda-agent/references/schematic-data.md#数据驱动架构基准)
是设计、检查和修复的统一规范正文；本文定义术语，不另立流程。
原始观测保留，源目标表达连接/归属/约束，算法生成，数据检查，失败回源重算，Apply 后回读对账。
新设计使用区内与纸张两层计算，不以旧九宫格、三层 tidy/move 或截图手工修补代替。

### 样例、参数与事实检查

样例是运行时可读的已执行做法：说明来源、开始状态、参数单位、命令、实际回读、错误修法和
验证状态。Agent 先选择相近样例，再替换参数并根据现场结果修正；样例不会冻结坐标，也不会
把一个题目的例外推广成通用规则。没有完成态答案或尚未连编辑器的内容标 `source-only`；
离线计算通过标 `offline-verified`；只有保存、重载并从真实文档回读后才标 `live-verified`。

检查结果分开解释：连接、DRC、几何、规则、评分分别陈述自己观测到的事实。workflow stage、
版本差异、评分和 staleRisk 可帮助定位问题，但不授权或拒绝普通 action。需要权威状态时，
工具批次执行 save → reload → readback；刷新失败就是数据不可用，不能靠阶段签字补足。

**开发验证场景**是一项用户可观察能力的可重现验收任务，保存问题、开始状态、参数、独立
验收要求、操作步骤、证据与未完成项。例如“保持已有组内布局，整体移动五个器件，再保存
重载核对”是一项场景；非对称 anchor、漏成员、固定件被动、旧快照等分别成为自动测试用例。
场景可以先于实现建立，此时为 `source-only`；它不是新的执行 DSL，也不替代单元测试或
从原始需求到成品的端到端回归。一项场景可以关联多个测试，同一测试可以服务多项场景。

场景分别记录**实现范围、自动回归、离线复现、现场持久化**，不能用一个 pass 统称完成。
只有前后数据、独立检查与该场景要求的现场证据齐全，才勾选其验收；局部场景通过不代表
整板 Layout 完成。PCB 组合移动的待办与执行顺序见
[开发验证清单](pcb-layout-validation.md)，可迁移步骤随公开 Skill 的样例发布。

## 本地设计比较与 Lib 内部计算

### eprj3 文件生成与校验边界

`.eprj3` folder 工程由 JSON 项目索引和 `.esch2` / `.epcb2` 等文本容器组成；官方
`easyeda-eprj3-skill` 可在不运行编辑器的情况下生成这些文件。文件生成、记录 Schema 校验、
电气/几何检查、宿主保存重载回读是不同的验证层，不能互相替代；生成 `POUR` 边界也不等于
已经计算出最终铜皮。格式文档、Schema 与真实文件发生冲突时，应保留对应版本和原始记录。

本项目若增加该输出路径，它应消费已有 canonical 连接与参数化几何，并维护稳定身份映射，
而不是让另一套脚本重新定义网络和布局。该适配器当前为 `planned`，官方脚本的离线测试不
证明本项目已支持它，也不改变现行 Web EDA / typed action 的现场操作约束。调研见
[官方 eprj3 Skill](ecosystem-survey.md#12-官方-eprj3-skill离线工程生成路线2026-09-21源码与离线实测)。

### PCB 参数化配置

`pcb config` 是当前 PCB 设计规则的参数化入口。它从新鲜官方规则快照计算局部修改，保留
未指定字段，再经 typed action 写入并回读。CLI 输入单位与每条规则的存储单位分别记录，
不得把输入的 mil 数字直接写入 mm 字段。安全间距按对象对、线宽按规则表处理；网络类成员
和网络类的规则绑定是两个独立对象，创建类不代表已经分配线宽规则。
写后回读只证明内存状态；持久化仍需 save → reload → readback。此入口不代表支持 EDA
全部系统偏好（网格、吸附等），也不通过恢复全局默认值来替代设置某一项。

### 通用局部布局内核与 Lib 适配层

`PlanSchematicLayout` 接收组件稳定 ID、实测几何、逐脚网络/NC/悬空状态、核心 ID 和
绘制策略，不要求 Lib、库 UUID、工程或纸张。输出局部 placements/wires/flags、评分和
候选用量。它是 app 包内可复用的纯计算 API，不执行 EDA 操作。
`sch layout-plan --from input.json --out geometry.json` 为普通器件集合提供离线入口；
`sch lib-layout` 校验 canonical/库身份/模块关系后调用同一内核，再进行整页组合验证。
独立局部结果不是 Apply 队列，不证明页边界、跨集合连接或现场身份已验证。

### PCB 布线求解内核与宿主适配

PCB 公共求解由四个可引用的纯 Go 包组成：`pcbmodel` 保存板、层叠、器件、焊盘、铜与刚体
变换；`pcblayout` 生成完整移动组候选并检查机械合法性；`pcbrouting` 求单次路径并共同选择
多网候选；`pcbsolve` 管理路由反馈、共享预算、排序与整体独立复验。四包均不依赖 Cobra、
daemon、Connector、文件系统或 EasyEDA 对象。

**宿主适配层**负责将原始快照和独立需求转换为内核输入，校验端点网络与层，并保存输入
溯源。单端点入口为 `pcb route solve/check`，布局与所有声明网络的入口为
`pcb layout solve/check/render`；不分发第二个 CLI、不通过子进程调用求解器。其他 Go 项目可
直接 import 同一 module。应用结果仍走既有 typed 执行链。

单次 `pcbrouting.Solve` 为单层、零过孔、直线/45°路径；`pcbsolve` 的二层闭环固定装配面，
组合 TOP/BOTTOM 与每网最多两个通孔，并要求全部声明网络共同存在。`found/pass` 只表示已找到
并回验满足传入约束的候选，不声明全局最优或未声明网络已布通。
预算耗尽、端点被挡或有限搜索未找到路径均为 `incomplete`，不能称全局无解。
四层/更多层、拆线重布、差分、等长与回流策略仍是后续能力，不因层叠模型可表达而变为已支持。

**多层布局布线协调（planned）**属于 `pcbsolve` 的长期职责：联合选择完整组位姿、各需求的
可用铜层与合法换层路径，并在层间通道占用和冲突反馈下重新求解。二层是当前实现范围，
不作为包职责的永久边界。层叠使用显式物理顺序和 signal/plane 角色，不能按层 ID 大小猜顺序，
也不能把 plane 当作空白信号层。器件装配面与线路铜层分别建模；支持更多铜层不自动允许
器件翻面。过孔占用按实际跨越的全部层检查；平面连接、避让与回流依赖明确几何和规则，
缺测保持未知。社区扩展顺序见[多层协调任务](pcb-solver-community-design-detail.md#a4多层布局布线协调)。

**布线通道预留**是临时板上共同试布得到的分层路径、线宽、净距和过孔占用，属于规划数据，
不写入板上铜清单。它绑定当前候选投影；模块移动后，所有声明连接重新求解，旧预留立即失效。
飞线方向或端点连线只能用于启发式引导，不能作为导通或通道容量的证据。

本轮先补“初步布局 → 共同试布 → 实际冲突 → 完整组让位 → 重新试布”的局部修复。
让位参数声明步长和相对原始位置的最大移动距离；求解器根据寻路实际碰到的对象动态扩展位置，
再检查板框、固定轴、外围所有权与已有铜。移动引起的机械冲突可继续驱动相邻可动组让位。
搜索耗尽不归因为某个器件阻挡。初始布局阶段提前估算通道方向/容量属于下一项优化，不能
以这里的局部修复能力宣称已经完成全局拥塞驱动布局。

### PCB 求解的可行性、最优性与确定性

**可行性**指候选在声明的完整需求下通过几何、电气及所有路径共同存在的检查；它不表示
指标最优。**确定性**指相同输入与搜索配置可复现输出；状态去重只消除重复探索，两者都不
证明最优解唯一。**最优性**必须限定目标、可行域和搜索完成证据；有限离散模型的穷举最优
不能推广为连续 PCB 布局的全局最优。多个布局可以具有相同的最优指标。

**宽松估计**在此指用于搜索的简化几何、线长或拥塞估计，不是放宽制造规则；没有证明的
估计值不能称为最优性下界，也不能替代最终精确复验。**独立精确参照**是在极小、明确的
离散模型上独立枚举合法布局及共同路径的测试程序；它不是再次调用生产求解器。参照搜索
未完成时，同样不能给出最优或无解证明。

局部修复与从零布局是不同优化任务；最小移动目标适用于前者，不能直接作为后者的通用
质量标准。开源依据、比较方法与尚未执行的二层验证计划见
[PCB Layout/Router 调研与验证计划](pcb-layout-solver-research.md)。

### PCB 模块候选

#### 联合布局布线问题

在同一份真实板快照和独立需求下，同时选择模块/器件的允许位姿，
并为每条必须连接的网络寻找可共存的铜路径。位姿、路径与过孔是决策变量；板框、锁定件、
焊盘归属、禁布区、线宽/净距和网络连通是硬约束。长度、转折、过孔数及非必要移动只在
满足硬约束后用于比较候选。有限预算内没找到候选是 `incomplete`，不是全局无解证明。
现有实现把它分解为 Layout 枚举位姿、Router 检查固定几何；这只是问题分解，不表示
当前已有整板联合最优求解器。社区贡献的范围与验收建议见
[PCB 求解社区设计](pcb-solver-community-design.md)。

**联合逃线预留 / 模块联动（offline-verified）**：零器件重叠与单网可达不能证明多网共同可布。
规划输入逐脚声明需连接端点、局部出口和明确 NC；同一候选内的逃线路径必须共同满足真实
焊盘、已有铜、板边及网络规则。出口连接到声明的目标方向，预留几何只存在于规划数据，
不以虚拟铜冒充现场连接。供电、GND 与既有通道也参与约束。局部逃线成功不证明整网布通。

让位以显式物理移动组为单位；功能区标签或画面中的“下面一排”不能替代器件/铜所有权。
固定核心可关联独立可动外围组，但逐脚归属保持。联动按目标模块平移、阻挡组递归平移、
其他位置/允许朝向的有限候选回溯推进；所有受影响外部连接重新求解，既有材料化铜由重建
产生。缺少对象归属或重建方法的组保持固定。搜索预算耗尽是 incomplete，不是全局无解。
候选保留需求哈希、移动原因、全部变换和共同通道，回读验收必须对照独立需求重新计算。
晶振模块可先在局部坐标组装完整器件/铜/禁铺/过孔，再以刚体变换放入板内；当前板声明 `tracks-vias`，晶振区禁止铺铜，只允许显式 GND 导线与接地过孔。旧保护对象必须凭对象身份和原始状态逐项替换。

Layout 与 Router 是相邻层：Layout 枚举器件/模块的平移、旋转和移动组，重算连接固定端点的
外部几何；每个候选投影为临时板状态后，由 PCB Router 公共内核验证固定几何下的实际路径。
多条路径必须在同一候选中共同存在，不能把互相占用同一窄缝的单网成功相加。Layout 不复制
通用 Router，也不把 Router 找到一条路解释成布局已验收。当前离线实现已覆盖逐脚出口、共同
冲突、有限预算及晶振局部刚体候选；首个 AT32F415 schema-v3 候选在 fresh module-check 中因
非规范同网铜重叠、逃线终点和对象身份对账失败而被拒绝并完整回退。离线搜索成功不证明这层
集成已完成，现场保存重载和模块联动实板证据必须分别报告。

`existingViasOnly` 是逃线需求的只读 witness 模式：只接受声明 PID、网络、位置和焊盘归属均与
fresh 快照一致的既有过孔，不创建新孔。它适合 U6 EP 等本来已有换层地孔的焊盘。候选的
`maxVias=0` 约束新增孔数量，不抹掉已证明的既有 witness。

PCB 的参数化布局把“关系”和“坐标”分开：Agent 从题目、机械图和原理图明确模块成员、
固定轴、装配面、板边/开口关系及 `member pad → owner pad`；`pcb layout-plan` 读取真实
footprint anchor、bbox、pads 与板框，有限枚举若干完整候选。算法负责刚体变换、逐脚外围、
避让和测量，Agent 根据具体事实选择，不能用同网最近距离重新推断所有权。

候选不是现场试摆，也不是审批状态。它必须包含全部成员的可执行位置、原始输入哈希、
板框中心线距离、component/keepout gap、每个最小间隙对应的对象对、缺测与铜覆盖限制；
不合适就修改源关系或搜索参数
并重算。`offline-verified` 只证明计算；执行后保存、真实重载和官方回读才构成
`live-verified`。现有评分、stage 和总分不决定候选能否执行。

带铜 schema-v2 候选若会触发 `pour-rebuild`，必须把受影响的既有材料化铺铜写成显式
`affectedBaselinePours`：记录 fresh before 的 boundary/materialized primitiveId、net、layer 与
从器件移动前后、routes、regions、pours、vias 推导的 `impactEnvelope`。这是一条局部差异白名单：
声明对象只允许在包络内重算，editable boundary、可读语义字段及包络外 polygon/孔洞/ARC 保持；
未声明对象全域保持。缺 inventory、fill、boundary 关联、net/layer 或 polygon 时结果是
unknown/error，不用 bbox 或空数组替代事实。

晶振护环中的“接地”是实际铜连通事实：每个声明的 fence/anchor via 都要在 TOP 与 BOTTOM
分别接触 fresh 实际 GND 铜并经实际路径连到 ground-anchor。`tracks-vias` 候选使用显式导线；
只有候选声明铺铜时才使用 materialized 铜岛作为证明。同名 GND、任意一个过孔被铜命中或仅
两条入口连通都不足以通过。OSC 则按电容→晶振→MCU 的 ordered path 证明，并把
fresh pad geometry、TOP/0-via、实际 track 子段/arc 子弧长度、转折和 apply PID journal 一起对账。

### Block Template 与公共 Lib Module

两者互补而不互相替代。Block Template 是由角色器件、固定内部拓扑、可重绑端口和约束组成的
**生成配方**；实例化后只剩普通 part、导线和虚拟组，`block` 不是运行时布局层。公共 Lib
Module 是 GitHub 版本化的数据资产：从 `draft` 功能证据开始，补齐确定拓扑后成为
`topology_ready`，再补齐库身份、完整 pin→net/NC 与官方实测几何后成为 `compose_ready`。
只有最后一级可以直接进入 `sch compose`。同一功能若已有 Block，Lib 记录引用它，不复制维护
第二份拓扑。

`sch design-diff` 按稳定 ID 比较器件/引脚/网络、库身份、位号及几何，并生成内容修订哈希。
比较完整 compose 计划时还包括纸张、导线、标记、框与标题；仅提供 connectivity 回读时，
图形层属于未验证证据。数组存储顺序不等于身份，模块的阅读顺序则属于设计意图。
本地数据一致不证明导出后的 EDA 仍然一致，也不自动决定覆盖方向。

`sch lib-layout` 消费已确定的电气图、官方测得的器件姿态/bbox/全部引脚与模块布局意图，
从指定核心开始，沿真实连接选择外围的几何参考脚，计算短正交导线，再输出 compose 源。
几何参考可以是已放置的外围，支持串联支路；它不增加网络，也不把未知脚补为 NC。
同网多脚可显式指定参考脚，所有物理脚仍按网络策略连接。电源与地允许局部重复标记，
内部信号必须形成实际线树。计算保持实测朝向，搜索有界；无解或证据不全返回具体对象，
不尝试任意旋转、扩纸、修改电气关系或现场试摆。

## 单页模块组合（SCH Compose）

**Lib 局部候选择优**：先安排仅连接电源/地的外围，再安排信号相关外围；分类依据网络策略，
不根据器件型号或位号猜测。沿真实引脚搜索，在首个可行的连接距离层内比较局部实线、
轴线对齐误差及可见包络面积，不再直接接受第一个合法坐标。完整放置后才统一计算命名，
最终评分包含命名与逃逸引线；避免每次试摆都重算整颗核心的密集标记。
局部电源/地优先尝试 80 raw 内的无碰撞直线/L 形合并，再生成 GND、电源、信号标记。
短距离阈值是有界启发式，不证明更远不能直连；仍保留每棵线树必需的命名点。
末端布线或命名失败会触发本区 checkpoint 回退，移动已放外围并重算受影响后缀；
每个 checkpoint 最多尝试 3 个不同 XY，总回退上限 32 次且不重置候选预算。
先定向尝试冲突网成员，再尝试包含异网导线所有者的完整阻挡集合；未知归属禁用剪枝。
这仍不是全局最优或无解证明，失败不能用放宽电气/文字检查来兜底。

**器件文字占位 `textBboxes`**：与当前器件姿态绑定的外置位号轴对齐矩形数组，
使用与 bbox/pins 相同的 raw 坐标；随模块平移。Lib 搜索和 Compose 将其用于器件、
导线及网络标记碰撞检查和框包络。它是输入的几何证据，不是文字编辑指令；现阶段
不由常规 list 自动采集，必须单独保留 Designator 类型、parent 与测量来源并回读核验。
矩形数组本身没有属性类型，生产者须排除型号/参数等非位号属性；不能让算法猜测矩形用途。
缺失不代表没有位号；旧输入的保守预留不能当成实测验收，导图不能替代缺测。

`sch compose` 消费完整 1.4 连接核心与各 Lib 的明确绘图数据，先计算紧凑标题和框，
再按功能顺序作 Z 字单页组合，每框保持紧凑高度、同行顶齐、整体平移。连接数据不随分页变化；
所有 pin→net、NC 或已知悬空都必须明确。不能从空画布推断被清掉的功能电路。
默认页边距、框内最小边距、模块间距均为 10 raw（0.1 inch/2.54 mm），标题净距为
5 raw，字高20。框内边距会因网格向外取整增大，不为等高行扩框；图签 keepout 必须避让。
生成 Apply 必须携带目标快照；重建非空页显式 `--replace`，写前核对快照，写后完整
核对器件、引脚、连接、NC及呈现层。放不下就返回数据错误，不缩符号或自动分页。

**端子直出声明**（`modules[].terminals`）引用原样位号与引脚编号，沿给定的器件外侧
方向生成一段真实引线和网络端口。长度按引脚、器件、已有导线及标记文字占位计算，
邻脚使用错落长短；它只改变呈现数据，不创建或推断 pin→net。无直线解时返回冲突。
器件位号和其声明顺序属于输入身份，组合、Lib 登记及 Apply 均不得自动改写。

## 一、电气层（1.4 连接核心）

### 原理图几何交叉与实体接点

**几何交叉**只表示线段占用相交坐标；**实体接点**才合并物理线岛。
EasyEDA Pro 3.2.186 的隔离页数据验证（2026-09-15）表明：严格位于两条正交段内部、
无引脚/标记/端点的 X 不合网，同名网 X 也不构成实体直连；T 端点接另一线则合网并切段。
一条 API polyline 的冗余共线中间点会消失，不能当作接点声明；分次创建的真实端点不同。
官方读取的扁平独立线段记录、API 输入的连续 polyline、渲染/对账派生的分割点必须区分。

规划与检查既验证几何占用，也验证物理接触分区；两者都不能由网名代替。
无节点 X 不加连接圆点，不满足专属外围直连；端点/T/重叠的异网接触仍是错误。
允许导线内部 X 不豁免引脚方向、器件本体、引脚 stem、位号或网络标记避碰。
其他宿主与未知形态不能由这次实测推出普遍兼容，必须回读，未知或拓扑变化即失败。

稳定连接模型见 [`schematic-connectivity-model.md`](./schematic-connectivity-model.md)。布局算法只读该模型。

### 已知悬空与未知引脚

`pin.connectionState:"unconnected"` 表示已确认无网络、无 NC 的悬空物理脚，
用于无损重建尚未完成的原理图。官方快照必须明确返回 `net:""` 和
`noConnected:false` 才能自动生成该状态；缺少字段不算证据。
它与网络连接、明确 NC 互斥；重建保留空脚并继续报告 `unconnected-pin` 警告，
不会把数据采集完整解释成电气设计合格。未声明状态的无网非 NC 引脚仍属于未知。

### 网(net)
一条把若干**引脚(pad)**连在一起的电气网络。原理图的连接、PCB 的连通性都以网为单位。
一个器件的每个 pad 带一个 `net` 名(如 `USB_DP`、`GND`、`3V3`);同名即同网、电气相连。

### local net vs global net —— `isGlobalNet`
- **global(全局网)**:`GND` / `VCC` / `3V3` / `5V` / `VBUS`… 电源与地,**几乎每颗芯片都连**。
- **local(局部/信号网)**:`USB_DP` / `MCU_RX` / `EN` / `IO0`… 把**特定两三颗器件**绑在一起的信号网。
- **为什么区分**:判断「谁是谁的电气搭档」只能看 **local 网**——global 网谁都连,拿它找搭档
  会选到「几何上近但电气无关」的芯片。工具里 `isGlobalNet()` 就是这条线;net-aware 决策
  一律 **local 优先,无 local 才退回全部网**。

### 电气同网与几何参考脚

多个物理引脚可以属于同一个电气节点，例如 AMS1117 的 pin2 与散热片（库内 pin4）
同属 VOUT。布局 `attach` 只选择画图时靠近哪个引脚，不代表只连接那个引脚。
输入/输出去耦属于模块的局部支路：即使它们连的是全局电源网，也应沿核心 VIN/VOUT
真实导线连续绘制。两只输出电容可共享右侧 pin4 的几何参考，同时保留 pin2 的局部
电源符号。每个物理 pin 的网名在 XY、朝向和导线重新计算前后必须一致。

`sch power-layout` 是该规则的四器件固定 LDO 实现：从实测 bbox/pins 计算竖直电容、
水平电源线与期望 pin 坐标；它输出可重复的计划。它不是机器学习模型，模板字段断言
也不等于图面验收；验收需覆盖多组尺寸/朝向/位置，并在 Apply 后比对真实几何和网表。

### 模块呈现（module frame）

模块的虚线框与标题属于布局呈现数据，不改变 component/pin/net。框的包络包含器件、
引脚、导线、电源符号及标注预留区。标题根据分项占位寻找上方或下方空档，能放入
现有包络就内嵌，空间不足才最小扩边，不固定预留顶部标题带。候选先比较框高度，
再比较面积，平局依次优先左对齐、顶部。1.4 默认框与标题使用粉色
`#AA00AA`，虚线 `lineType=1`，标题字高 **0.2 inch = 20 个 0.01 inch 坐标单位**。
本版不提供独立 Notes 创建和“每模块必须有说明”的检查要求。

器件分区包围判据：器件本体与位号（如 Q1、Q2）须在框内；型号、参数等
非位号属性文字不参与页面碰撞或入框判定，不因这类文字重叠/越框扩框或阻断验收。是否显示属性
是独立的呈现选择，不能通过修改真实料号或参数来伪造简短文本。

转换器接收明确的框坐标与样式，通过官方 API 创建，回读位置、尺寸、颜色、线型和
标题字号逐项比较；布局数据还可携带预测文字包络和障碍物，由实际文字 bbox 验证
是否超出预测范围或发生碰撞。文字尺寸估算与 API 实测值分开记录，不能把估算当作
渲染验收。只存在图元 ID 不构成通过。相同输入重复 Apply 不增加图元。
契约与命令见 [模块呈现转换](./schematic-frame-conversion.md)。POWER 是这条转换链路
的验收样例，样例画成功不能代替代码回归。

### 模块 Z 字行布局

先压缩各模块的框和标题包络，再按功能顺序从纸张左上角向右排模块，宽度不足时进入下一行。
各框保留自己的高度、同行顶齐，下一行按上一行最高框推进；不按原始随机 XY 排序。模块内器件、所有 pin、wire 端点
和电源标记整体平移，连接和方向不变。单页装不下即报错，不自动增加分页。
共享行规划器用于 compose 与 POWER，可组合多组不同高度模块。有实测 `sheetBorder` 时，
虚线实际笔画到图纸内边框最少留10 raw并内取网格；缺失边界的兼容回退会在计划中明确标识。

### net-class(网络角色分档)—— `netRole` / 规范线宽 / 电源铺铜
`isGlobalNet` 只把网二分成「电源地 vs 信号」;**net-class** 在电源侧再细分成**载流角色**,
驱动两件事:走线该多宽、该不该走铺铜。分类器 `netRole()`(`internal/app/pcb_netclass.go`)
按**网名/电压**启发式给角色(块声明的 per-net 宽度可覆盖):

| role | 判据(net 名) | 规范宽(§7.8,seed 自 live 规则) | 铺铜倾向 |
|---|---|---|---|
| `gnd` | 含 `gnd` | (走线 20mil,但**优先 pour**) | 全板 pour / 内电层 |
| `high-current` | `VBUS`/`VIN`/`VBAT`/`VSYS` 或 ≥9V | ~20mil | pour / fill |
| `power-trunk` | 5–9V(如 `+5V`) | ~15mil | pour |
| `power-branch` | <5V 或无电压名(`3V3`/`1V8`/`VCC`/`VDD`) | ~10mil | pour(局部) |
| `signal` | 其余(非 global) | live 默认(细间距可收窄到最小合规宽) | 走线 |

- **消费点**:`route-short` 按角色查 `netClassWidthTable()` 给宽(不再是 20/10 二分桶);
  `pcb net-classes` 打印当前表;`pcb check` 的 **width-under-spec**(电源线 < 规范宽)+
  **power-not-poured**(电源网未铺铜)把关;2 层电源铺铜 `pcb power-pour`、4 层 `power-planes`。
- **铁律**:width 维度与「该不该 pour」维度**共用同一个 `netRole` 定义**——否则「电源该多宽」
  与「电源该 pour」两套判据漂移。规范线宽是**设计惯例非制造规则**(live DRC 规则只给单一默认宽),
  故内联 Go 为真值 + `fab-rules-jlcpcb.json` 文档镜像;精确值由块 `signals.track_width_mil` 声明覆盖
  (`improvements-sink-to-blocks`,消费待 block-apply)。

### 网感知(net-aware) vs 几何(geometric)—— 本项目的核心决策二分
| | 依据 | 例子(连接器分组选边) |
|---|---|---|
| **几何** | 只看 X/Y 坐标 | 「这些连接器质心离哪条板边最近 → 就贴那条边」——不问它们连到谁 |
| **网感知** | 看电气连接(net) | 「这些连接器主要连到哪颗芯片(local 网)→ 贴那颗芯片所在的边」 |

**判据一句话:让「谁挨着谁」由电路连接决定,而不是由当前谁离谁近决定。**
几何决策会把 USB 拉到离它搭档 CH340 很远的边 → 差分对横穿全板 → 交叉暴涨;网感知把 USB
放到 CH340 同侧 → 短、少交叉。实测(ceshi 同种子 A/B):几何 61 交叉 → 网感知 28 交叉。

## 二、布局对象与分档(placement tiers)

`pcb place-constrained` 按**固定的四档序**布局,高档先锁死、低档只能在其空隙里填:

| 档 | 对象 | 处理 |
|---|---|---|
| **T1 孔** | M3 安装孔 / 挖槽(layer-12 fill) | 障碍,永不移动;其他件避让 +60mil 垫圈净空 |
| **T2 边缘件** | 连接器 / 模组 / 天线(`board_edge=true`) | 贴板边 + 锁定;**user-facing 分组、any 就近**(见下)|
| **T3 主芯片** | ≥8 脚芯片 / 晶振 / `anchor=true` | 保持种子位、冻结(**工具不做主芯片 floorplan——种子由 agent 给**)|
| **T4 卫星** | 去耦/上下拉/LED/按键 | 螺旋合法化,**net-aware 吸到搭档芯片**;不冲突的保持原位(不扰手调)|

### edge role —— 边缘件的**三种**边语义
块 `placement.<ref>.edge` 与 S0 spec 的 `interfaces[].facing` 声明边缘件的**边角色**,
工具据此分流(`edgeRoleOf`):
- **`user-facing`**:USB / SD / 螺钉端子 / 排针——用户插拔的外部 I/O,外壳要开孔。**≥2 件时
  分组到同一条共享边、沿边居中紧凑排布**;共享边由 **net-aware** 选(搭档芯片所在边),
  外部 I/O 聚一处又不拉长网。diag 标 `:grouped`。
- **`any`**:RF 天线 / 无线模组——必须在**某条**边(缩短天线走线),但哪条都行 → 保持各自最近边。
- **`internal`**(#168 新增):只在**箱内**连线的连接器——备份电池座 / 板间排针 / 内部排线口。
  它**不需要**外壳开孔,因此**不该占板外沿**:外沿是稀缺资源,应该留给真要出线的对外口;
  内部件占了外沿会挤掉对外口的可达边,而且电芯辫线还得从边上绕回箱内。
  证据来自 box-v2 rev-a(4 层车载盒子,166 器件):`J1 = PH2.0-3P` 是接**箱内**电芯的备份
  锂电池座(`J1.1=VBATT / J1.2=GND / J1.3=TS_NTC`),却和车辆端子、Type-C 一起挤在底边外沿。
  判据落成 `pcb check` 的 `internal-on-edge` 规则,并作为 `pcb layout-score` 的 `edge-io` 维输入。

**语义来源与置信度**(三层,冲突时越具体越优先):

| 来源 | 表达 | 冲突时 | finding 档 |
|---|---|---|---|
| **S0 spec**(板级决定) | `interfaces[].facing` / `internal: true` + `ref` 钉位号 | **最高**——这块板的具体决定 | WARN |
| **块库**(类别通用知识) | `placement.<ROLE>.edge` | 次之——器件类别的一般经验 | WARN |
| **启发式**(兜底推定) | 网络不含对外语义网 + wire-to-board 类封装 → 推定 internal | 最低 | **INFO** |

启发式命中只报 INFO 是刻意的:推定错了不该像显式标注那样理直气壮地拦人。

匹配:优先读块 hint(独特 designator 前缀 JP/SW/LED/ANT),通用前缀 J*/U* 走 device-name
regex 兜底(regex 是块数据的镜像)。**注意 `PlacementIndex.ByRefPrefix` 明确跳过 <2 字母
前缀**,所以 `J1` 这类通用位号**永远拿不到块数据**——而 internal 判定的主要目标恰恰是它们,
这就是为什么 `internal` 必须能从 S0 spec 进来。**仍不解析自由文本 `orientation`**——那要
`blocks show` 摊给用户。

### 插头护套包络(plug envelope)
连接器**插头**(而非 PCB 上的母座)的外壳宽度。母座 footprint 不重叠 ≠ 插头插得进去:
Type-C 粗线插头的护套明显宽于母座本体(母座 ~9mm,护套 ~12-13mm),两个口挨太近时插头
物理打架、手指也捏不进去。这是 `layout-lint` 的 overlap 与 `pcb check` 既有规则都抓不到
的——它们只看 footprint/courtyard,不看插头三维包络。

几何里**根本不存在**这个量(PCB 只有铜箔和渲染 bbox,3D 模型也不给尺寸),只能查表:
`internal/blocks/data/_plug_envelope.json`(按 device-name 子串匹配,与 `openings` 同范式)。
查不到时回落到 bbox 宽 + 余量并在 finding 里标 `plug-width=fallback`——**估算值必须自曝**,
否则用户会把一个瞎猜的宽度当实测。判据落成 `connector-plug-clearance` 规则。

### 布局质量的可计算维度(layout dimensions)—— #167

「好布局」不是玄学。审一块外包交付的 box-v2 布局(166 器件 / 4 层 / 4G+GNSS 双 RF)时,
它肉眼「赏心悦目」的地方拆开看**全是能从几何 + 网表算出来的属性**。`pcb layout-score`
把它们拆成九个各自 0-100 的维度:

| 维度 id | 测什么 | 数据来源 |
|---|---|---|
| `partition` | 功能分区不串:模块 bbox 互不交错、内部紧凑 | spec modules[] 或信号网连通度聚类 |
| `flow-order` | 信号流向单调(电源→数字→RF→天线) | spec `flow` + 模块质心沿轴的 Kendall-tau |
| `edge-io` | 对外口聚一条边、开口朝外;内部件不占外沿 | 板框 + `facing` + 插头护套表 |
| `protection` | 保护件贴端子(fuse/TVS/ESD)、去耦贴 IC | 同网 pad 最近距离 |
| `tidy` | 齐整:落格 / 朝向一致 / 位号同侧 / 字号统一 | 器件 rotation + anchor + 丝印(#153)|
| `compact` | 紧凑不真撞:板面利用率 | bbox 面积 / 板框面积 |
| `rf` | RF 馈线短 + keepout 全层 | 天线同网 pad 距离 |
| `routable` | 可布性:ratsnest 交叉**密度** | 复用 `layout-lint` 的 MST 交叉 |
| `clearance` | 装配间距:tight pair + 手焊通道 | 复用 `layout-lint` 的间距/#99 |

三条设计约定(违反了这套度量就不可信):

1. **「没测」≠「测了满分」。** 数据或意图缺失的维标 `skipped`,**不参与加权**且必须给出
   原因。默认给满分会让第 5 点的校准判据失效——一块什么都没测的板会拿满分。
2. **硬错不抹平分数。** 跨网短路 / 器件重叠 / 出板框进独立的 `blocking` 列表一票否决,
   不进加权。旧 `layout-lint` 一处重叠就把分数打成 0,其余维度的差异全被抹平,
   看不出布局到底好在哪差在哪——这正是要拆多维的直接动机。
3. **计数与判定同源。** `verdict` 只从 `blocking` 数和 `overall` 推,单一产出点。
   聚合类命令在这里踩过「0 个阻塞项却 FAIL」的判读陷阱。

**归因是一等产出**:每维要给出「是哪几个器件拉低了它」及各自扣分,这是打分驱动精修环的
梯度来源。只给分数不给归因的维等于没做——你知道 62 分,但不知道该动谁。

**校准闭环(第 5 点)**:拿一块公认的好板跑分,它就该得高分;**某维在好板上得低分 → 是度量
错了,回去改度量,不是改板**。好板 dump(`pcb dump`)进 fixture 做回归:度量改了 / 规则加了,
好板一跑分数不该掉。权重表(`defaultDimensionWeights`)是**待校准初值**,不是真理。

落地在 `internal/app/testdata/boards/`(约定与「怎么加一块真板」见该目录 README),
`make layout-calibrate` 跑,全离线。两条补充判据:

- **参考板必须配一块负对照。** 只断言「好板得高分」时,一个退化成恒返 100 的度量照样全绿。
  负对照 = 同一块板逐维注入一个缺陷,断言九维**全部**掉到 100 以下——它守的是「度量还
  醒着」,正对照守的是「度量不吵」,缺一不可。
- **断言是阈值型不是精确值。** 度量本来就是要被校准的;冻结精确分数会让权重一动就得重刷
  全部 golden,于是没人再敢动权重,恰好把这个闭环锁死。
- **合成板只能验自洽性,校准必须用真板。** 照着判据手工摆出来的板拿满分是同义反复,
  它证明不了拐点定在 0.20 还是 0.15。当前 fixture 全是合成板,这是范围声明不是成绩。

### partner chip(搭档芯片)
一个连接器/卫星**电气驱动的那颗固定主芯片**(经共享 local 网)。net-aware 布局的目标点:
卫星吸到它、连接器组贴它所在的边。工具里用 `mainNetPads`(net→主芯片焊盘)+ `nearestPad` 找。

### 原理图侧的刚体:虚拟组(L1)与功能电路(L2)—— 用户定义,2026-08-15

<a id="原理图侧的刚体虚拟组-l1-与功能电路-l2--用户定义2026-08-15"></a>

以下是旧图维护的历史概念，不是当前生成许可。代码中的 clusters、持久 group 与导线
连通分量并不必然相同；现行功能所有权以显式 zone 核心/成员为准。
旧图存在“芯片与外围靠标签分离”可作为原始观测保存，不能把它当成新目标布局的合格基准。
新求解须遵守真实直连和外围跟随约束；物理连通分量不足以替代功能所有权或完整区内求解。

**L1 虚拟组 = 导线连通分量。** 被**真实导线**连在一起的一切算一个组:器件本体 + 桩线 +
marker(netflag/netport)+ 它们的文字带。**只靠网络标签同名相连的不算连在一起** ——
那是两个独立的 L1 组(去耦电容与它的芯片、跨页同名网,都是分开的)。

**L2 功能电路 = 若干 L1 组按功能聚合**(芯片 + 它靠网络标签联系的外围)。块实例天然是一个
L2。对更上层(区/页)它同样是一个刚体。

**两层同一条铁律:组的体积 = 它所有元素的并集;同层的组之间不许重叠。**

用户原话:「虚拟组是左右连线在一起的算一个虚拟组,只要分开没有链接都是一个独立的虚拟组;
芯片+外围没链接的电路(网络标签分开的也算)构成功能电路,也算一个大的虚拟组概念。」

为什么这个定义是对的:**导线连通分量是唯一"挪一个必须一起挪"的单位** —— 拆开它就要删线
重连(会踩「相邻共线导线自动合并 → 串网」),而 L2 之间只有标签关系,整体平移不动电气。
所以 L1 是刚体的**物理**边界,L2 是刚体的**语义**边界。

与代码现状的错位(修之前的实情):`sch group` 的持久虚拟组是**按块实例**分的(一个块 = 一个组),
既不是 L1 也不完全是 L2;而块内布局判占地只算**器件本体**,marker 完全不在占地里。于是
`layout-lint` 默认排除全部非 part 图元,一直报 0 overlap —— 判据本身看不见这一整类问题。
实测(ceshi,单块 ch340c):按 L1 口径 6 个组、**2 对整块重叠**(U3 的 marker 域把贴在它
电源脚上的 C7、C8 整个罩住),且 J1+D1 那个组左沿到 x=−26,**已经探出图纸**。

## 三、块(block)—— 本项目定义的一等功能概念

### 块是什么
**块 = 一段已在真板上端到端验证过的「外围功能子电路」,作为可复用单元。**(CH340 USB 转串口、
ESP32 双三极管自动下载、SY8089 buck、RS-485、GNSS 前端、microSD…)。不是零散的器件、也不是
一整块板,而是**功能粒度**的电路积木——「点灯」「USB 烧录」「5V→3V3」各是一个块。

**当前定位**:blocks 是拓扑配方(`parts/internal_nets/ports`)加设计知识，已有 `sch block-apply`
实例化能力；不等于普通 zone 必须先注册块。复用看 verification/就绪证据，不能把
“JSON 中有字段”理解成“工具已执行该约束”，更不能把单个块成功当整页布局或现场验收通过。

### 三层库(器件 → 块 → 流程)
- **器件层** `standard-parts.json`:role → LCSC/UUID,选型单一源。
- **块层** `internal/blocks/data/*.json`:把器件按功能组成子电路 + 携带多维放置/信号/丝印知识。
- **流程层** design-flow(S0–S6/P0–P10):把块编排进整板流程。
块 `parts.<role>` 指回器件层、`block` 引用被流程层的 S0 方案书 module 引用——三层串起来。

### `verification` 证据(块的分项可信判据)

`schema_version: 2` 起将验证拆成 `schematic`、`component_selection`、`pcb_drc`、`bringup`
四个独立阶段,每阶段记录 `status` + evidence/issues。只有四项均为 `passed` 且显式
`production_ready: true` 才显示 `ready`;原理图拓扑通过但尚未投产就绪时显示 `verified`,不能把
"拓扑可复用"误读为"选型和实板均可靠"。

迁移期间保留 legacy `validated` 字符串兼容旧块;一旦 block 存在结构化 `verification`,它就优先决定
状态。新贡献不得只依赖非空字符串声明 ready。拓扑证据允许免去重复推导,但跨块边界仍需核实;
器件选型、PCB 和 bring-up 是否可信必须分别读取对应 stage。

机器约束由 `internal/blocks/data/_block.schema.json` 和 `go test ./internal/blocks/` 共同执行:前者约束
稳定字段类型/必填项/枚举,后者检查 standard-parts 外键及 role/port/internal_nets 引用闭合。

### 消费与贡献
- **消费**:`easyeda blocks ls/show/search`(go:embed 进二进制,**离线、无需 daemon/窗口**);手工接任何
  已知外围**前先查块**(铁律 8)。
- **贡献**:手接并端到端验证过的新外围可回流入库,但优先保持核心 manifest 简洁；只有已有或即将实现的
  消费器需要某项约束时才新增结构字段,解释、经验和项目复盘留作文档内容。
  朝向/贴边/间距等改进若已有确定性消费者,沉淀成声明式数据；否则先作为手册说明,不为未来猜测提前扩 schema。

### 块数据模型(多维 map)

`internal/blocks/data/*.json` 是块拓扑的声明式来源,同时暂存部分设计说明。下表必须区分“工具已消费”与
“仅供 Agent/人工阅读”;未消费字段不是机械保证:

| 字段 | 内容 | 谁消费 |
|---|---|---|
| `parts.<role>` | role → `standard-parts.json` 的 LCSC/UUID | Agent/人工选型入口；仍按 verification、供应状态和项目适用性判断 |
| `internal_nets` / `ports` | 块内网表 + 边界端口(功能名) | 原理图实例化(`verification.schematic=passed` 时复用已证拓扑,仍验跨块重绑)|
| `schematic_layout` | role → `{dx,dy,rotation}` 原理图相对坐标模板(y-UP，`+dy` 向上，5 格对齐，须覆盖全部 role) | `sch block-apply`(模板优先于网格;原点避碰 + 落后 overlap 回读)|
| `placement.<ref>` | `board_edge` / `edge` / `side` / `orientation` / `severity` / `reason` | T2 边缘件(edge 已消费;side/orientation 待补)|
| `openings` | `[{match, local}]` 连接器开口本地方向 | T2 朝向(旋到开口朝板外)|
| `pcb_layout` | `*-adjacency`(去耦/晶振贴脚)/ `rf-keepout` / `ep-*` | T4 贴脚(待消费)/ P4 禁布 / P8 热焊盘 |
| `signals` | 差分对 / 阻抗 / 等长 | P7.0 关键网先行 |
| `silk` | 逐脚标注 | P9 丝印 |

**source-of-truth 分层**:选型 = standard-parts;拓扑 = internal_nets;外部电气事实 = datasheet/官方参考;
板级工艺参数 = 当前项目 stackup/fab profile。blocks 对外部手册多为摘要和引用,不是这些事实的最终来源。

**投资门槛**:在继续扩 schema 或全量迁移前,先用一个简单块完成最小 `sch block-apply` 闭环
(放置→连内部网→绑定 ports→check→实例 manifest)。只有该闭环能稳定减少操作和返工,才继续投入稳定
net ID、全量 verification、provenance 和复杂 PCB constraints；否则保持“简洁 manifest + 手册”。

## 器件身份、位号与功能角色

`component.id` 是连接图中的稳定、不透明实例 ID；`component.ref` 是图上显示的
器件位号；`component.role` 是功能角色。三者不能相互推算：不能截取 ID 生成位号，
也不能将 `RF_MCU`、`AUDIO_MODULE` 等功能名称写入位号。旧 ID 即使含有旧位号，
修正显示位号时仍保持该 ID 不变。

正常位号使用器件库默认前缀加数字。前缀取官方 device 的 `property.designator`，
不能凭器件用途猜测端子一定是 `J`；实际库可能使用 `U?`、`CN?` 等前缀。
已有合法数字位号保留原拼写、前导零和声明顺序。只为非标准名称或未编号占位符分配
未占用数字，功能名称保留在 role。原生 `uniqueId` 保持不变，避免影响 PCB 关联。

| 原理图覆盖/布局 | 目标所有权/直连对账 + 实测本体/位号/线/标记/框逐页检查；覆盖不足列未验证 | 单独 layout-lint、同网/同框、高分、截图 |
| PCB 器件覆盖/间距 | `pcb layout-lint` | 截图(stale/blank)|

### 4 层叠层规格(客户确认 2026-07-13)= GND 主导

- GND 在 顶/内层1/底 三层,电源(3V3+5V)埋内层2。**必须一次 `power-planes` 在干净板上做对**——**别反复 pour/翻层**:实测反复操作会累积 netless 死铜(挡顶层铺铜填充)+ 把 PLANE 绑定 pour-rebuild 降级成 netless@L1(L15 绑不上),把板子搞脏。CLI **无 via-create**:电源缝合过孔靠 `power-planes`(plane 网)或 `route-short --route-power`(信号层电源,会打缝合过孔,但顺带画冗余走线)。

### Type-C 端子突出板框(P3 一次做对)
受体连接器(USB-C / DC jack)mating 面**突出板框 ~0.5–1mm**(焊盘留板内,板框在端子正下方内缩让位)——P3 定板框时做,别等布线后再改(返工)。见 `pcb-layout-conventions.md §2.2`。

### 布线排序铁律(2026-07-13 实测踩过)
- **布线顺序由板级约束决定**(P7.0):使用整板自动布线、且次级电源轨分散时，应先布好并锁定
  电源骨干，避免信号占满通道。关键网需要严格 TOP/0 via、并采用逐模块参数化布线时，可先
  预留电源通道，依次完成关键信号、相邻短线和普通信号，再落电源主干与支路；每批都要检查
  后续电源和 GND 回流仍有连续空间。两种顺序都不能把电源空间推迟到最后才考虑。
- **散布电源轨走信号层铺铜,不穿细线**:8 个散布 5V 焊盘无法用细线干净连;焊盘在顶层就**顶层铺一片 net-bound pour** 直连(`pour-fit --net 5V --layer 1`)。**同层多网 pour 靠优先级**:顶层 GND pour 优先级高会把 5V 挤没 → **删掉/降低竞争的 GND 顶层 pour** 让 5V 独占该层(「2 层接地」由 GND 内电层 + 底层 GND pour 兜)。
- **tier② 原生自动布线** 布信号:route-short 84 clearance 的板,原生路由器 Track-to-Track 降到个位数(推挤/撕绕/规则原生一致);前提=P7.0 关键网/电源先布并 `track-lock`,对话框选「保留 + 只顶底层 + 忽略已在平面的电源网」。
- **孤立铜清理**:被 `track-lock --all` 锁住的残留短轨桩 rip 不掉 → 先 `track-lock --net X --unlock` 再 `rip-up --net X`。
## 芯片功能 Zone（原理图计算层）

功能 zone 是一个已确认功能核心（芯片、接口或晶振等）与其专属外围的布局所有权边界，不是 Lib 库资产，
也不是 PCB zone。每个独立核心对应一个 zone，器件只属于一个 zone；共享外围必须明确归属
或作为独立功能区的核心，不能通过共同 GND/VCC 自动并区。计算输入显式列出成员，
保留完整引脚、网络和 NC；区内求解，区间由 compose 排版并生成独立框。
引脚对齐指外围接线端点到宿主引脚出线轴的垂距，不等于器件中心对齐。

**Zone 归属复核提示**是基于源引脚网络和显式 attachment 的启发式诊断，不是新的
ownership 权威。`sch zone-review` 提示多个多引脚器件、排除声明的电源/地后不与核心
相连的子图，以及仅靠声明电源/地建立的 attachment。AI 根据器件功能与设计证据决定
保留或修改源 JSON，再重算。提示不自动拆区、不改变网络，也不证明真实导线已连接。
未命中规则不等于功能归属正确；位号、坐标和网名拼写不参与这些规则。

### 两层布局与统一间距

局部层只处理一个 zone 的局部坐标、连接和可见占位；核心固定，失败时允许回退和移动
本区已放外围，重算线路，不能修改其他 zone 的内部数据。外层只处理完整 zone 矩形的位置：
内部尺寸不变可复用旧位置，尺寸变化才需要重排矩形；重排不改变其他区的内部几何。
跨 zone 信号通过已声明的命名端口连接；若要求跨区实体连线，则还需要跨区路由与通道占位，
不能假定矩形不碰撞就意味着跨区线路也合法。

统一间距 `spacing` 是框呈现约束，不是引脚 pitch 或电气净距。启用时同源派生 zone 内边距、
zone 间净距和页边净距；相邻框只加一次间距，笔画半宽另计。zone 框必须包含器件、引脚、
线路、标记、位号、自由文字和标题的必检包络，排除非位号器件属性文字。
原生测量与估计占位分别保留来源；缺失必检文字或图纸内框
不能写成实测完整。A4 可放置区域是内框内缩后的区域减去图签等禁放区，不只是宽高或面积。

局部回退是有限候选搜索，不是最优性证明。失败或预算耗尽不给完整效果；输出同一份
经过连接/几何校验的目标数据，固定渲染器只转译，不重新摆件或补线。

### 无边界通道布局

`layoutMode:"unbounded"`（CLI `layout-plan --unbounded`）选择展开式局部布局：保留实测
姿态与功能归属，器件分列，每网分配独立通道，以较大图幅换取少量位置尝试。它不限制
区域或纸张宽高；框按完整结果生成，直接 `layout-render` 可查看无纸张预览。仍有有限
计算预算，不承诺任意输入必定可解、紧凑或美观；无法通过电气与几何校验时不输出布局。
默认省略该设置仍使用原局部搜索；无边界模式不同时进行旋转优化。
`layout-plan --lib` 将既有 Lib canonical 数据适配到相同的局部求解层，保留各模块的
连接策略和归属，输出多区结果；纸张组合仍是独立步骤，不伪造更大的实测纸张。

原理图允许导线内部的 X 形相交，不产生连接点；不同网的端点接触、T 接触、共线重叠
仍拒绝。符号本体、位号、引脚出口也仍需避让。直连指真实导线路径，可有转折与交叉，
不表示必须一条直线。此规则适用于两种布局模式，不是 PCB 走线净距规则。

### 网络标签布局

用户明确不要求器件间实体直连时，可选择 `layoutMode:"net-labels"` / `--net-labels`。
该模式保留同一电气网表、器件与引脚、核心/外围归属和实测姿态；各器件独立标注同名
网络，标签通过真实短引线连接引脚，器件按完整可见包络排成行列，不设纸张尺寸上限。
它明确替代本次绘图的 direct/attachment 实体连线路径要求，原始源数据不改写，结果和
报告记录此模式；不能称为“原实体线树保留”。attachment 的引脚引用与同网条件仍校验。
默认模式不变；不得在普通搜索失败时擅自切换到标签布局。标签/符号/位号/引脚出口
碰撞、NC 和异网接触继续检查，密集引脚的命名仍有有限预算，不保证任意符号可解。

### 功能子电路拆区与排版关联

拥挤区可显式拆出完整子电路：核心与专属外围一起迁入新 zone，保留唯一组件归属、
引脚、网络和 NC；不是仅按器件数量分组，也不要求子电路能够脱离主控独立工作。
跨区信号须明确改用 module_port 绘图策略，区内仍优先直接连接。此次接口不自动识别或拆分功能。
拆分后比较包含新标题、端口和内边距的总框面积、线长及最终页数，不能只报告母区缩小。

`zones[].placement:{samePageAs,preferAdjacent}` 表达原理图页层的排版关联：
samePageAs 引用另一现有 zone，是可传递的硬同页约束，不是器件所有权或嵌套父区；
preferAdjacent 为可选软偏好，只针对所引用的区，在合法位置中优先缩小两框距离。
引用缺失、自引用或只有偏好却没有同页目标应拒绝。放不下时不得静默拆散同页集合；
有界搜索失败不能冒充几何无解。同页关联与下述阅读流正交，不能为相邻偏好打乱阅读流。
关联只影响完整矩形的页号与位置，不改变区内几何，也不把原理图间距转换为 PCB 间距。
晶振等敏感子电路的 PCB 物理贴近约束仍须独立遵循器件设计指南。

### Zone 的 Z 型阅读流

纸张层的 `sheet.flow:"z"` 表示行式矩形排版：从左上开始，同行从左到右且顶部对齐；
放不下时回到左侧，按该行最高框加固定净距推进下一行。短框保持自己的高度，
不在短框下方回填后续 Zone，也不回填已结束页面。Z 型不是蛇形（第二行不会反向）。
Zone 数组是功能阅读顺序，不按面积偷偷排序。同页连通集合按最早成员的位置聚拢，
集合内保持输入顺序并整体换页；软相邻不能越过硬同页、纸边、图签、净距及阅读流约束。
这是 `layout-sheet-plan` 的默认流；`sheet.flow:"compact"` 显式使用旧自由装箱进行比较。
改变阅读流属于页层约束变化，即使旧坐标不碰撞，也必须重新验证/排版；区内几何不变。
Z 型优先可读顺序，不承诺最少页数；纸张和框内留白不能为迁就页数而被缩小。

### Zone 的有限形态候选

形态候选是同一 Zone、同一器件与引脚连接的另一份完整合法局部几何，不是新 Zone 或新电路。
显式 `optimization` 启用有限优化；`components[].allowedRotations` 声明允许的绝对正交存储角度，
省略时保留实测姿态，核心锁定，不自动镜像。旋转须同步引脚、包围盒与文字占位并重新布线。
原来同一物理导线岛内的引脚不得拆为多个同名标签岛；网络名相同不等于保留了直接连线。
最多保留 4 个候选（含原合法方案），用稳定 ID 标识；宽、高、面积、线长均由完整可见几何计算。
优化失败或额度用尽保留已验证候选；首次布局未成功仍失败，不伪造保底布局。
纸张层校验候选的组件/引脚/网络/NC 及刚体尺寸一致，只在候选之间选择并平移；
仍遵守 Z 阅读流和同页集合，不缩放符号、不现场拼接不同候选的导线。候选搜索有界，不保证最优页数。

### 已选页的固定 Apply 转换

已选页是纸张规划器输出的一整份几何权威数据，不是再次排版的请求。
`compose --layout-page` 将它与同页 canonical 身份/连接、局部模块几何及新鲜现场证据绑定，
验证一致后只作局部到纸张的刚体平移；spacing、框、标题和 sheetPosition 原样保留。
坐标、引脚、线路及文字占位一起转换，不能混用候选或退回默认间距重新排版。
固定转换不等于现场已同步：仍执行原受保护队列、接线前实测和最终回读；
纸张估计保持估计来源，也不提供跨页迁移事务。

端口的**占位长度**是符号本体加外置网名的轴向长度，不是引线长度。错长预算按该占位
归一化，不以最短引线作为分母强行平衡长短。包络按朝向取本体与文字的并集，不镜像扩边。
**命名点瘦身**是在同一真实线树上更换端口接出引脚/方向，不拆网、不改元件姿态；
共享端点或 T 接合法，命名引线重复覆盖已有导线则应改接出点。
内容包络变小不保证含标题的框面积同比变小，更不等于 A4 已放得下；最终仍由实测纸张的
compose 排版验证。固定预览需显示端口占位和真实接点，不能把绘图简化误当成布局压缩。

## V4 宿主与新数据模型

EasyEDA Pro 产品版本、扩展 API 引擎版本和 easyeda-agent 发布版本是三个独立概念。
项目主线宿主从 2026-09-21 起为 EasyEDA Pro V4；`extension.json` 的 `engines.eda: ~3.2.0`
仍是官方扩展 API 引擎约束，不应随产品版本机械改成 4.x。`easyeda health` 分别报告宿主兼容性
和 CLI/daemon/Connector 一致性，两者都不代替对象级回读。

V4 的多符号、多器件、多封装是“一个逻辑库记录关联多个可选实现”的变体模型，不等同于
传统多单元符号的 `subPartName`。canonical schema 没有显式 variant ID、选择规则与映射时，
必须在写入前拒绝，不能取数组第一项。引脚 `otherProperty`、逐层 pad stack、槽孔形状和 3D body
属于对象保真字段；读不到时标为不完整，不能以基础坐标/网络相同代替。

V4 自定义位号是项目级格式策略，不再等同于固定的“字母前缀+数字”。canonical Document 可用
`designatorPolicy:{mode:"custom",pattern:"^...$"}` 声明一个锚定 RE2 格式；工具只验证和原样保留，
不猜编辑器内部的递增规则。省略策略仍使用 classic 规则，历史功能名必须先迁入 role 再分配编号。

### 晶振相对定位的有限搜索

`crystal-guard` 的横移原点来自 owner 与晶振信号焊盘对的中点；离开 owner 的距离从实测
成员包络与指定 gap 起算。`search.crystalOffsets` 把有界网格、障碍边界与焊盘对齐事件组合
成有限候选。边界包围框只产生搜索种子，最终铜仍需精确几何检查；某个有限搜索集零候选不构成
全局不可行证明。完整 bundle（外部信号、护环、禁铺、过孔）必须在每个位置重新生成，器件位置
合法不能代替铜合法。字段与失败处理由公开 Skill 的 PCB 布线 reference 维护。

### 晶振保护的三种边界

敏感禁铺轮廓覆盖成员和完整 OSC 信号 stroke；GND 护环围绕晶振与电容，保留真实信号
入口；外围孔围栏是闭合的 via-center 轮廓，按周长核验节距。三者不能统一替换为包含
MCU 端点的大矩形。外部信号伸出局部围栏不等于漏掉信号禁铺保护。障碍感知搜索允许
轮廓曲折，但不能进入成员敏感包络、自交或静默删除不合法孔。几何轮廓不证明接地，
完整候选及实际回读仍分别检查每段护环、局部地焊盘与地锚点的真实铜连通。
