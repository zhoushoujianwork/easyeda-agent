## 修复与运行说明

`pcb.component.delete` 先通过官方 `getAll` 读取当前板器件 ID。请求内任何 ID 不存在或
为空时，整批在写前拒绝；有效 ID 才交给官方 `delete`。离线 typecheck 与 519 个连接器
测试通过，`make skill-check`、`make local-build VERSION=v1.6.0-dev.18` 通过。
Codex 在 Web 扩展管理器卸载 `dev.17`、导入同 UUID 的本地 `dev.18` 包并重新启用
“允许外部交互”；typed `web reload` 成功，耗时约 10 秒。`health` 与测试回包核对运行
版本，完成后用 typed `sch open` 将前台恢复至 P3。

## 下一步门禁

B03 查找子项已恢复，下一步在可清理前置条件明确后继续 create/open/export 的单项报告。
之后定位 B06 原生标签 API 返回空对象；B08 改用原本就是自定义规则配置的专用板，

语义判据逐字段解释 ID/坐标变化。B01 的 Skill 对照、B10 的最终独立复核和旧版通过项
的同版重测完成前，B00–B10 不能称全绿。

## 故障归因校准

- **我们的方法或实现负责**：B01 是审计未做完；B08 在需要可还原的原板上改写系统预设，
  试验台选择错误；B10 的配置残留由此产生。B10 旧版过期 ID 抛宿主内部异常，连接器缺少
  写前 ID 核对；dev.18 已修并在现场验证。B03 的旧 18 秒有效等待不足以覆盖实测约
  19.4 秒的团队扫描；CLI 补丁增加默认预算到 90 秒，两次现场返回完整结果。
- **尚未确定**：B03 未计时每个官方子调用，不能指认哪个最慢或证明 reload 是成功的
  必要条件。B09 也未建立重载前后的稳定语义映射。
- **上游嫌疑较高但未坐实**：B06 的 CLI 参数顺序与官方 `createNetLabel(x,y,net)` 一致，
  标签落在真实导线端点，调用很快返回空对象且 fresh 回读无标签；同页 netport 成功。
  该官方接口标为 BETA。仍需最小 typed 复现及明确宿主错误，才能定性为上游缺陷。
- **只是版本证据缺口**：B04、B05、B07 在 dev.14 通过，在 dev.18 尚未重放；不能写成
  dev.18 的“失败”。
