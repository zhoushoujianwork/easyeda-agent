## 方法与故障归因

- **已修复并实测**：B03 查找原来的有效预算约 18 秒，不足以覆盖 52/53 工程完整扫描。
  默认总预算改为 90 秒、支持 `--timeout` 后完整查询通过；实际约 17–21 秒。
- **我们的实现缺口**：过期 PCB 修改未像删除一样预检 ID；区域创建回包回显请求名称，
  缺少 fresh 名称验收。两者已定位，尚未修改运行时。
- **待隔离的宿主交互**：原理图引脚读取与后续修改/NC 失败有时序相关，typed reopen 后
  恢复已证实，不能断言读取是唯一原因。net_label 在干净 reopen 后约 0.019 秒返回空，
  增加超时无帮助；尚无足够证据确定上游内部原因。
- **修正测试基线**：规则测试改为新板主动建立自定义配置11，再冻结并恢复；名称保持。
  首次初始化仍发现孔间距 0.3→0.2999994 mm，超出机器尾差，CLI 正确拒绝签 verified。
  两个 inactiveColor 差异发生在配置初始化、重载和层数切换整个过程中，缺少紧邻层数
  写前快照，不能单独归因 stackup。区域只能确认名称回读失败，不能断言原生存储丢失。
- **已澄清的判据**：B09 本轮生成属性的父对象/键/值/可见性/坐标全部一致；SVG 非 ID
  属性、文本、树结构一致，38 个变化 ID 均无引用；网表字节相同。因此本轮持久化通过。
  不将这个结论补签到旧版尚未解释的 PCB 隐藏属性坐标变化。
