## 需要修复或补测的点

1. **重连**：daemon 重启后 90 秒无窗口；后续连接恢复发生在只读观察浏览器标签后，
   因此不能给自动重连通过。P3 内容回读时器件、导线和属性内容相同，但属性 ID 被重建。
2. **工程枚举**：`project find` 超时且 daemon 留下 abandoned request；同窗口之后的 `project info`
   和导出成功，说明不是持续断线。需要定位官方枚举或连接器调用的超时位置，再测创建/查找/打开。
3. **net_label**：`sch netflag --kind net_label` 创建失败；`net_port_bi` 在同一网线端点成功。
   应区分该 kind 是否宿主不支持、参数错误或 handler 缺陷，补对等正负例。
4. **重载对象一致性**：临时原理图页重载前后组件、导线、网络和属性内容一致，但 22/119 个
   属性 `primitiveId` 改变；原 P3 在多次重载后也出现属性 ID 重建。PCB 铜、器件和规则
   相同，`silk` 的隐藏 Footprint/Device 坐标由 `(3600,3500)` 变为 `(0,0)`，显示位号仅有
   浮点舍入差异。这些可能是宿主规范化行为，但在对象身份/完整快照判据明确前 B09 不通过。
5. **规则预设恢复**：测试前的 `JLCPCB Capability(Two Layers Board)` 是系统预设；typed
   写规则按命令契约生成每板自定义副本。规则数值已恢复，测试网络删除后对应 net rule 也消失，
   但目前无 typed 命令选回原系统预设。故测试板仍有配置名称残留，B10 不算完全清理。

独立复核确认临时对象已清零、配置名称残留及 B09 对象差异。B02 没有预设的 90 秒性能指标；
本轮仍标 `blocked`，原因是连接只在浏览器标签被观察后才回到 daemon，缺少无人干预自动重连的
证据，不能凭最终连通状态补签重连过程。
