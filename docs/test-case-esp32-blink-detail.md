# 最小点灯板：执行与记录

[返回需求主文档](test-case-esp32-blink.md)。只把其第一节交给执行 Agent，不提供旧 BOM、UUID、
网表、坐标或答案图；本页给测试协调者使用。旧最小用例来源为 Git `90c7c21^:docs/test-case-esp32-blink.md`。

## 一次完整用例

| 步骤 | 执行范围 | 留下的证据 |
|---|---|---|
| 1. 起点与选型 | 核对 health、实际包/源码版本及工程/文档 UUID；从原始需求选型，读取真实引脚、封装和规则 | 原始需求 SHA256、空白或复用文档基线、生成的器件/连接/参数源 |
| 2. 单页原理图 | 按数据驱动 S0–S6 生成、Apply 并检查供电、启动、下载接点及 GPIO→限流→LED→GND；未用脚明确 NC | 一份源数据、执行 journal、完整器件/pin→net/NC 回读、layout-lint 与 DRC；显式 save→reload→fresh readback |
| 3. 两层布局 | 一次同步 PCB；核对实例、焊盘网络、两层叠层、板框、天线禁铜及位号；参数化布局 | fresh dump、整板图、通用两轮自检证据；用户确认最新保存版后再布线 |
| 4. 布线与终检 | 按所选两层方案完成全部必接网络；铺铜仅在设计需要时使用，不调用四层 power-planes | 焊盘/导线/铜及网络对账、0 overlap/越界、PCB DRC 无错误且 Connection=0、极性与接口丝印 |
| 5. 落盘与收尾 | 显式 save→真实 reload→fresh dump/DRC，导出原生工程及整板预览，汇总独立复核和成本 | saved:true、重载后的对账和导出、一个结论；清理本轮创建对象或记录专用工程保留状态 |

各阶段复用[公开设计流程](../.agents/skills/easyeda-agent/references/design-flow.md)，不再展开新的分段签字清单。
稳定点保存，失败停止依赖写入、保留输入和已写状态，再修源数据或工具；不在现场试摆或用 GUI 补做。
用户已授权复用的容器可以保留；测试前核对 UUID 和基线，只清理本轮对象，不清空已有 ESP32 工程。

## 按改动补专项

默认只跑上面这一块板。局部移动、写前拒绝、中断恢复等用例仅在本次变更影响对应能力、
或既定发布材料明确要求时补测，复用这块小板或基础测试证据，不另建复杂开发板。
写前拒绝以前后完整对象一致为判据；恢复以实际写入状态和保存重载为判据，不能用清空重建代替恢复。

中版本材料仍按[材料格式](releases/evidence/README.md)记录 M1/F1/F2/E1/L1/L2/N1/R1/E2E：
M1 为本板真实测量，F1/F2 为单页与 PCB 建模，E1 为本板电气，E2E 为上述完整闭环；
其他 ID 使用与声明范围一致的专项及证据。未执行项如实记 not-run，不用本文修改覆盖检查器要求。

## 最少记录

一份报告包含版本/工程身份、输入及源参数哈希、实际命令与回执、fresh 回读和 DRC、
保存重载结果、整板图、独立结论、未通过项及一笔 `easyeda audit cost`。
截图不能替代对象回读；仅设计验证通过不能标实板点灯通过。新用例当前为 not-run。
