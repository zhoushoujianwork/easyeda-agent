## 结论与现有实现证据

1. 现有有限候选和有预算搜索可以找到可行解，**没有 PCB 布局全局最优或唯一最优保证**。
   相同输入输出相同结果、去掉重复状态，都不构成最优性证明。
2. 宽松几何、估计线长与拥塞适合生成和排序候选，最终必须用真实焊盘、铜面积、净距、
   板框和所有路径共同合法性验收。粗略筛选若会排除合法解，还会影响搜索完整性。
3. 最小移动适用于已有板的局部修复；从零整板布局需要另定目标，不能沿用最小移动排名。
4. 优先验证路由冲突反馈驱动模块让位；多起点模拟退火适合离线质量对照。强化学习暂不
   作为二层 MVP 的实现前提；先借鉴它的实际路由评估方法。
5. MCP/Skill 主要解决数据读取、操作封装、分析与工作流。工具数量和自然语言演示不能
   证明自动布局质量，仍要用相同约束和预算的独立测试比较。

## 建议的职责边界

以下公共边界已用于二层协同求解；存量 auto-place、九维评分和专用模块策略仍通过宿主适配
逐步迁移，不能把新 MVP 表述成所有历史算法均已删除：

| 包 | 目标职责 |
|---|---|
| `pcbmodel` | 宿主无关板、器件、焊盘、铜、规则、所有权、层叠、几何变换 |
| `pcblayout` | 放置、约束、合法化、模块/晶振策略、完整组让位与布局检查/测量 |
| `pcbrouting` | 固定几何下的单网/多网路由、路径优化及独立路径检查 |
| `pcbsolve` | 候选投影、路由反馈、搜索预算、去重、排序及最终独立复验 |

`internal/app` 保留快照/库适配、Cobra、文件输出、渲染和 typed Apply；运行时 PID 映射
留在宿主层。公共包不依赖编辑器、daemon 或 Connector。`pcbsolve.Check` 从原始板和独立
需求复验，不调用 `Solve`、不信任候选自报通过或自报指标。

首版固定装配面，允许原面平移及声明的旋转，支持 TOP/BOTTOM 路径与有预算的通孔。
不增加翻面、差分、等长、自动铺铜。层叠数据从第一版表达有序铜层、信号/平面角色、平面
网络及过孔跨层范围；只有层数的旧数据不推断内层用途。局部逃线已有的换层能力与新的
公共板级联合求解能力必须分别报告，不能互相代替。

## 验证计划

已有相对布局的组合移动按 [开发验证清单](pcb-layout-validation.md) 逐项推进。该清单记录
用户可观察场景与待办，本节保留算法验证设计；自动测试通过不等于场景的现场验收完成。

2026-09-24 的路线避让审查确认这套职责可形成闭环，同时发现固定排网顺序及初始旋转
淘汰会漏解。已补有预算的排网次序回溯和移动后的整体旋转邻域，并以固定布局两网、双组
递归让位/外部端点重算场景核对。具体红绿过程和能力边界见
[运行记录](reviews/2026-09-24-pcb-route-avoidance.md)。这证明有限模型中的避让能力，不把
同层路径枚举、真实带铜模块 Apply 或整板现场验收宣称为完成。

### 1. 先冻结问题、基线和目标

验证三条线：正确性、相同资源下的优化质量、现场持久化一致性。硬约束先成立，软成本
不能换取违规。局部修复对合法候选按下列向量作字典序比较，不合成总分：

`移动组数 → 总位移 → 旋转次数 → 新增过孔 → 实际线长 → 转折数`

从零布局另定目标和测试集，不因摆在初始位置“零移动”就判为好布局。

每次基准保存代码 commit、未提交差异及哈希、原始输入和需求哈希、单位、坐标约定、
规则、搜索配置、随机种子、依赖及机器/线程信息。工作树持续变化时，不只记录 HEAD。
外部格式转换不能静默丢弃固定组、禁布区、铜归属或规则；无法等价转换的案例单列为
unsupported 并解释原因，不混入公平性能比较。

### 2. 典型案例与失败测试

沿用 [现有板案例约定](../internal/app/testdata/boards/README.md) 的原始 board、独立
spec、独立 expect 分离思想；新增求解案例目录在实现时确定，不覆盖已有评分 fixture。
每例记录来源、开始状态、需求及单位、独立期望、验证状态。先写失败测试，再实现，再回归；
期望以约束、连通性和指标边界为主，不复制求解器输出坐标作为答案。

| 案例组 | 必须证明的行为 |
|---|---|
| 基础几何 | 非对称封装绕 anchor 旋转正确；成员、焊盘和归属内部铜同步变换 |
| 机械约束 | 板边接口、开口、安装孔、禁放区、固定轴保持；凹板框不能只查 bbox |
| 核心与外围 | MCU 去耦、串联电阻、LED、LDO/DCDC、晶振遵循明确所有权 |
| 共同通道 | 两网分别可达但不能同时通过时拒绝成功；先选路径占用后续网络空间 |
| 路由驱动让位 | 没有器件重叠但线路受阻，依据实际冲突移动完整组；预算耗尽不作为阻挡归因 |
| 多组联动 | 阻挡组递归让位、遇固定组回溯；每次移动重算外部连接，状态去重避免循环 |
| 二层换层 | TOP 受阻时按规则走 BOTTOM；检查过孔铜面积、孔径、净距及网络预算 |
| 层限制 | TOP-only 不换层；通孔焊盘跨层障碍正确；异面器件占用分别判断 |
| 电源与既有铜 | 局部回流、内部铜、固定连接不被破坏；同名 GND 不等于物理连通 |
| 独立复验 | 篡改路径、漏移动成员、未知铜、缺测、旧快照均被识别；不信自报指标 |
| 宽松估计反例 | 粗略几何通过而精确净距失败时淘汰；估计线长降低但联合布线失败时不得推荐 |
| 资源与失败 | 布局、联合路由及单次寻路共享总预算；取消/超时保留已经找到且通过复验的合法候选 |

变形测试使用网格对齐平移、90° 旋转及输入重排；板框、端点、方向约束等同步变换，层
约束保持等价。检查电气结论和对应指标，不要求等价最优解具有相同坐标或输出排序。
规模测试分小场景、几十器件、已有大型参考板，记录时间、状态和内存。

### 3. 独立的小型精确参照

先用 2～4 个移动组、每组少量合法位置/旋转、小型离散路由图建立穷举参照，不把大型
精确优化器开发作为 MVP 的前置项目。穷举同时考虑布局与共同路径，约束与被测模型一致：
层、线宽、净距、路径域、过孔上限和目标向量均明确。

参照不调用生产 `Solve`；极小图形尽量使用独立几何判断或手工可审查的合法路径集合，
避免双方共用同一缺陷。只有穷举完成才能证明该有限模型最优或不可行；预定义路径集合的
穷举只证明该集合内的结论。预算耗尽不给证明，也不外推到连续空间。

指定的极小验收例要求被测算法找到已知可行解，并达到参照的最优向量；多个等价解均可
接受。一般规模案例只报告相对质量，不能因为几个小例最优就声明求解器全局最优。

### 4. 同预算策略对照与消融

| 策略 | 比较目的 |
|---|---|
| 冻结的现有有限枚举 | 兼容性、成功率和性能基线 |
| 冲突反馈＋模块让位 | 本轮主要改进策略 |
| 固定种子的多起点模拟退火 | 离线搜索质量对照；不是直接采纳 SA-PCB |

比较布局策略时使用同一个 Router；比较 Router 时使用同一批固定布局。历史端到端结果
与这种受控对照分别保存。增加关闭路由反馈的消融，以及粗筛启用/关闭的对照，定位收益
是否来自真实冲突反馈，观察粗筛是否漏解。

首次实验建议使用种子 `0..9`、总预算 `1/10/60 秒`，相同机器和线程，统计整个布局、
路由与复验耗时；另记录各阶段耗时。以上是待冻结的默认配置，不是实测结果。正式比较
前声明主要指标、非退化条件与调整预算的原因，不能看完成绩再挑种子、案例或阈值。

报告联合布通率、硬约束违规数、目标向量、状态数、耗时和峰值内存，随机策略展示全部
种子及中位数/较差分位数。指标只在合法候选上比较；失败没有线长不能当作零线长。
missing/incomplete、unsupported、invalid、timeout/canceled 分开解释，保留全部失败案例。
候选是否可行、搜索是否结束、是否有模型内最优证明分别报告：搜索未完成也可能已有合法
候选；规定只保留三个候选也不意味着后面没有更优候选。

改进结论至少要求必测正确性全过、必测案例布通率不退化、预声明的质量或资源指标有改善；
其他代价的变化同时列出。没有优势或出现取舍就据实报告，不以综合布局分数上升代替。

### 5. 二层 MVP 的验收

场景包含两条竞争通道的网络、一个多成员可移动组和固定障碍：

1. 通过极小独立参照证明原布局在声明模型中不能同时满足两网；一次寻路失败不足以证明。
2. 求解记录输出实际阻挡对象、位置和冲突网络，依据反馈移动完整组并重算外部连接。
3. 独立检查确认最终两网共同合法，固定对象及未移动对象保持，所有成员和内部铜一致。
4. 输出原布局、失败候选、最终候选的整板与局部 SVG，显示真实焊盘、既有铜、线宽、净距、
   过孔和移动原因。候选 JSON、渲染及 Apply 消费同一投影，像素不作为连通性证据。
5. 保留最多三个合法候选及事实指标；同时报告搜索是否完成，不声称全局最优或全局无解。

## 社区算法与多层协调的可行性复核

复核日期：2026-09-24。决策入口是[社区主方案](pcb-solver-community-design.md)，任务与验收契约归[详细稿](pcb-solver-community-design-detail.md)。本节记录判断依据，不新增生产能力。范围为数学建模、四包边界、多层扩展、算法选型、验证与社区组织；没有运行外部求解器，没有操作 EDA，没有发布 Issue 或推送代码。

### 1. 结论与置信边界

**建议继续推进：以完整电路块为对象，维护者定义题目和可信验收，社区贡献有限范围的求解改进。** 数学化、包隔离和多层协调均有可行路径。当前证据不足以支持“把任意整板交给社区算法即可自动完成”，也无法预测志愿贡献者数量。

| 需要判断的事情 | 本次结论 | 依据与限制 |
|---|---|---|
| 能否转为数学问题 | 可以，是约束满足、几何判定和组合优化 | 位姿、路径、层与过孔都是变量；未表达的电气要求不会被自动保证 |
| 四包是否适合社区协作 | 适合，目前不需要再拆仓 | 依赖隔离和离线回归已成立，稳定公共 API 与统一质量评价仍需建设 |
| 布局和布线是否应协调 | 应当协调，保留各自搜索职责 | 共用通道使两者耦合，路由反馈可减少仅优化估计线长带来的误判 |
| 多层是否可沿用架构 | 可以，需扩展模型、几何检查和跨层搜索 | 当前只支持二层；层数增加不是只放开一个校验条件 |
| 能否让社区推动进展 | 有条件可行，组织结果未验证 | 可复现的小任务降低门槛，核心评审、规则与宿主工作仍需维护者持续投入 |
| 是否已经能验证整板质量 | 不能 | 文件案例小，真实需求覆盖、带铜执行、回流与现场验收都有缺口 |

这里的“可行”是基于源码和外部先例的工程判断，不是成功率、排期或最优性承诺。

### 2. 数学化的范围与求解难度

可将问题写为：在声明的约束集合内，选择每个电路块的位置/旋转，以及各网络的连通几何，优化用户指定的目标。有限位姿与路径上的变量和约束已在[社区数学模型](pcb-solver-community-design-detail.md#数学模型与当前接口)说明。

| 子问题 | 可用数学表达 | 不能省略的真实含义 |
|---|---|---|
| 模块放置 | 连续坐标加离散角度，或有限位姿选择；不相交、边界与固定关系约束 | 核心与专属外围、内部铜必须按声明整体变换 |
| 单网寻路 | 带方向和层状态的图搜索；边成本为长度、转折、换层等 | 路径具有宽度和净距，检查整段铜，不能只查中心线节点 |
| 多网共同布线 | 多条路径/连接树的共同选择及几何冲突约束 | 一条路径先占通道可能让另一条失败；同网多端需要整体连通 |
| 布局布线协调 | 上层调整位姿，下层试布并反馈冲突；共享资源预算 | 搜索失败不等于该布局不可布，也不能凭一次失败永久删掉它 |
| 电气与制造规则 | 可计算的硬约束、经过验证的简化规则，必要时调用专门分析器 | 缺少电流、边沿、器件要求、参考层或材料数据时保持未知 |

数学问题不等于有简单公式或能廉价求全局最优。例如仅 10 个块、每块 8 个允许位姿就有 `8^10 = 1,073,741,824` 个位姿组合，尚未计入路径、排网次序与换层。这个计数是搜索规模的说明，不是当前算法的实测复杂度。

将位置和路线离散后，CP-SAT/MILP 可以为小问题提供精确参照，也可用于局部合法化。CP-SAT 要求整数约束，明确区分 `OPTIMAL`、`FEASIBLE`、`INFEASIBLE` 与 `UNKNOWN`；选择网格、整数精度和候选集合本身就限制了结论范围。[OR-Tools 官方说明](https://developers.google.com/optimization/cp/cp_solver)

建议生产路径继续采用有预算的启发式和独立复验，小型参照用于检测漏解与衡量质量差距。45° 路径的实际欧氏长度与整数化成本可能不同；若 oracle 使用近似成本，必须声明误差或只对其离散目标报告最优。无需为首批社区 PR 引入大型精确求解器运行时。

LLM/Skill 可以把用户需求和器件资料整理为可审查的约束，求解器负责计算候选；两者都不能代替输入真实性和电气检查。刚体模块能保留已验证局部结构、降低自由度，但可能错过需要重排内部元件的方案；这种失败应报告模块约束限制，不能擅自拆散模块。

### 3. 外部先例证明了什么

以下为原始论文、项目源码或官方文档，均为 `source-only`。没有在本仓相同输入/预算下复现，因此不采用其成绩为本项目收益预测，也不据此给算法排名。

| 来源 | 核实的做法 | 对本项目的意义与边界 |

| [tscircuit 路由数据集](https://github.com/tscircuit/autorouting)及[autorouter](https://github.com/tscircuit/tscircuit-autorouter) | 有算法数据集、可视化、固定种子 benchmark 与非 TypeScript 接入；路由器支持将 bug 报告转为 fixture/test | 与“社区解题”的组织形态接近，值得借鉴贡献体验；仓库存在不证明我们能获得同样的人力或算法质量 |
| [Quilter 放置控制](https://docs.quilter.ai/guides/placement-guide)及[物理约束范围](https://docs.quilter.ai/physics-constraints/overview) | 官方工作流提供分组、固定放置和约束表达，并说明未支持要求可预放置/预布线 | 支持明确设计意图和有限自动化范围；这是厂商能力说明，不是独立性能证明，也不改变本仓 typed 操作规则 |
| [KiCad 9 PCB 文档](https://docs.kicad.org/9.0/en/pcbnew/pcbnew.html) | 区分贯穿/盲埋/微孔、逐层 padstack、孔净距和层叠长度 | 多层模型要表达物理结构与制造规则，不能只有路线的起止层 |
| [TI SLLA414A，第 3.4～3.5 节](https://www.ti.com/lit/pdf/slla414) | 高速回流依赖参考平面，跨越空洞/分割或换参考层需专门考虑 | 导通和几何净距不足以证明高速正确；具体数值只适用于相应器件/场景，不能直接成为全部板的统一规则 |

选型判断：本期保留现有 Go 内核，借鉴外部方法并做可选对照；若未来在等价约束下外部 Router 明显更好，可采用适配器，而非预设一定重写或一定外包。Freerouting 仓库标 GPL-3.0、Cypress 标 Apache-2.0、tscircuit autorouter 标 MIT；代码移植、数据再分发和可执行程序集成分别核查来源及许可证，不把论文公开等同于任意复用授权。

### 4. 当前代码的实际准备程度

本次核对的四包代码基线为本地 `dev@9b00977`，本轮未修改算法实现。源码与测试优先于早期计划描述。

| 核查项 | 当前事实 | 对可行性的影响 |
|---|---|---|
| 包隔离 | `go list` 显示四包仅依赖标准库及彼此；没有 Cobra、daemon、connector、文件或网络 I/O 依赖 | 算法贡献者可以离线工作，抽包不是仅目录改名 |
| 真正的协调 | [solve.go](../pkg/pcbsolve/solve.go)投影布局、共同试布、累计预算；[joint.go](../pkg/pcbrouting/joint.go)有候选与排网次序回溯 | 可以增量改进现有闭环，不必再写第二个协调器 |
| 二层边界 | [layout.go](../pkg/pcblayout/layout.go)的请求校验调用 `board.Validate(true)`；`Demand.MaxVias <= 2` | 多层当前明确未开放，修改应覆盖模型/检查/生成整条链 |
| 路径候选 | [geometry.go](../pkg/pcbsolve/geometry.go)通常每个允许层求一条路线；换层策略枚举端点附近有限孔位与三段路径 | A2 有明确改善空间，但不能宣称某个尚未构造的反例已被解决 |
| 独立复验 | `pcbsolve.Check` 从原板与 moves 重建候选，不调用 `Solve`；`routeChecker/segmentClear` 等几何判定被两条路径复用 | 对篡改与控制流错误有效；无法独立发现同一几何实现的共同错误 |
| 精确参照 | [solve_test.go](../pkg/pcbsolve/solve_test.go)已有两个偏移、两条固定水平路线的手写独立枚举 | 已有起点，A1 要扩展覆盖而非从零重复造例；尚非通用联合 oracle |
| 数据完整性 | [model.go](../pkg/pcbmodel/model.go)有层角色、平面网络、region 和过孔起止层；没有完整孔型/逐层 padstack/介质/回流表达 | 足够作为扩展骨架，尚不足以约束一般多层物理问题 |
| 几何规则 | 当前全局 Rules 加逐需求 Width；两层孔按当前整体规则检查 | 多层网类/层相关净距和孔工艺不能靠循环更多层解决 |
| 宿主交付 | CLI 有 solve/check/render，历史记录有 layout-only 保存重载；完整内部铜 Apply 等仍列为待办 | 算法 PR 可以先成立，但产品能力升级还需要独立集成工作 |

六个公开文件案例的规模来自实际 JSON 统计，不能与全部单元测试的覆盖混为一谈：

| 文件案例 | 器件 | 移动组 | 连接需求 | 期望 |
|---|---:|---:|---:|---|
| automatic-channel | 4 | 1 | 2 | 合法让位 |
| fixed-route-order | 4 | 0 | 2 | 换排网顺序后通过 |
| joint-channel-negative | 4 | 0 | 2 | incomplete，不能报全局无解 |
| multi-group-clearance | 6 | 2 | 3 | 多组移动后通过 |
| route-feedback-two-net | 4 | 1 | 2 | 反馈移动后通过 |
| two-layer-via | 2 | 0 | 1 | 两通孔换层后通过 |

[BenchmarkSolveDozensOfComponents](../pkg/pcbsolve/benchmark_test.go)增加了 48 个远处器件，但沿用原有两条 demand。它验证障碍扫描增加后的开销，**不是几十器件完整网表的布通率或扩展性试验**。这使“先建设真实任务集，再开放算法竞争”成为本轮最重要的工程前提。

### 5. 多层如何沿现有分工推进

保留 `pcbsolve` 作为协调者是合理的。新增层不改变“候选布局 → 共同试布 → 冲突反馈 → 复验”的结构，但会改变可用空间、约束和搜索规模。

```mermaid
flowchart LR
    I[原始板与独立需求] --> M[pcbmodel 物理模型]
    M --> L[pcblayout 位姿候选]
    L --> S[pcbsolve 候选与预算协调]
    S --> R[pcbrouting 共同寻路]
    R -->|路径或冲突反馈| S
    S -->|完整组调整| L
    S --> C[从原始输入重建并检查]
    C --> O[候选与事实指标]
    O --> H[宿主适配与现场验收]
```

公共 `pcbrouting.Solve` 当前仍是单层；二层组合与板几何主要在 `pcbsolve/geometry.go`。扩展时可以将可复用跨层路径能力归入 Router，保留回调或明确的数据接口，避免把所有多层策略继续堆进协调器。无需立即新增第五个包或通用插件框架。

必须先解决以下四类差异：

1. **物理层叠与可走层不同**。层 ID 不表示上下顺序；四层板也不必然提供四层信号路由空间。器件装配面仍单独固定。先使用已声明层叠，不同时搜索制造商、层数和材料组合。
2. **换层动作与孔的物理影响不同**。电气路径只从顶层转到某个内层，贯穿孔仍占用贯穿板厚的钻孔和相应铜区域；需要检查中间层、异网平面隔离及实际可制造的孔型。盲埋孔不能从允许层列表推断。
3. **plane 不是一整张永远连通的 GND**。需检查实际填充区域、孔洞、连接与隔离；放置/布线改变后填充可能变化。首次实现可固定已经回读的平面几何，对会改变填充而无法复验的情况明确不支持；动态铺铜需另有可靠生成/回读链。
4. **几何可达与电气成立不同**。参考层缺口、换参考层、局部回流和高速规则需明确输入。先检查可声明的几何规则，阻抗/时延/串扰/温升等按数据和专门模型逐项支持，不能用一条“回流评分”概括全部物理效果。

顺序建议：A4 模型与拒绝负例 → 固定层叠的分层几何搜索 → 带实际平面和回流声明的案例 → typed 应用与真实重载。四信号层是算法诊断场景；SIGNAL/GND/GND/SIGNAL 和 SIGNAL/GND/PWR/SIGNAL 用于检验不同约束，不将其中任何一例直接宣布为通用高速推荐层叠。更多层提高潜在容量，也增加分支选择，不保证同预算更快或更优。

### 6. 算法投入优先级与验证方式

| 方法 | 推荐位置 | 当前取舍 |
|---|---|---|
| 有界替代路径、撤回重寻、排网选择 | A2，共同通道反例 | 最贴近已有回溯接口；先证明新增路线确实改善同预算结果 |
| 拥塞估计、网络分离、局部搜索 | A3，初始候选及候选排序 | 借鉴研究方法；估计只作引导，不作不可布证明 |
| 多起点模拟退火或大邻域搜索 | 更大模块组合的离线对照 | 先有可重复质量基准；不得仅因算法名称常用就更换生产路径 |
| CP-SAT/MILP/穷举 | A1，小型精确参照、局部合法化 | 对有限模型能建立强基准；不预设能承担整板详细路由 |
| 分层图搜索与层分配 | A4，固定层叠与显式孔型 | 先完善几何检查、范围声明和预算，再扩展内层 |
| 学习式放置/RL/生成候选 | 后续研究路径 | 目前缺少规模化、规则可信的数据和稳定奖励/评价器，不作为首批前置依赖 |

评价工具应分别覆盖：小型可穷尽题、真实模块局部题、完整网表板级题，以及故意缺测/违规的负例。增加器件时同步增加连接需求、密度、移动组与通道竞争；二层、四层、六层分别记录，不按器件数单独声称规模突破。

建议先选一块有授权可公开的真实模块板，提取完整外部连接和固定几何，在相同规则下构造不同密度/通道宽度的变体；后续加入不同封装、板形和多端网。开发案例与独立选取的验证案例分开，后者由维护者运行后公开结果，避免只针对一个手工样例调参。此数据集扩充尚未执行。

公平比较按前述[同预算策略对照](#4-同预算策略对照与消融)执行，并补充：不同算法的一个“状态”未必等价，跨实现比较需要同时限制墙钟、线程和内存；状态数适合诊断同一实现。外部 Router 的转换若丢失规则，标记该例不适用，不能静默把问题变简单。候选经统一 checker 后，真实 DRC/回读继续提供另一层证据。

性能改善不能抵消任何硬约束失败。局部修复和从零布局使用不同的目标；当前优先少移动的向量不能直接用作新板优化奖励。先冻结评价标准再看结果，保留失败与预算耗尽；多端网统计实际必需连接的覆盖，不能把多条端点路径条数直接当整网成功率。

### 7. 社区是否真的能推动

可贡献性已具备：公共 Go 包、文件输入、回归测试以及本地的社区文档和 CI。可持续社区尚需验证。tscircuit 的公开数据集和 bug-to-fixture 流程说明这种参与方式能被做成工具；本项目仍要自己完成第一份可复现的示范，而不是只发一个“实现多层布局布线”的大任务。

GitHub 只读核查记录：2026-09-24，[本仓库](https://github.com/zhoushoujianwork/easyeda-agent)默认分支为 `main`，查询返回 534 stars、70 forks、0 个 open PR；`dev` 的 `pkg/pcbsolve` 目录存在，但 `docs/pcb-solver-community-design.md` 在远端 `dev` 和 `main` 的内容查询均为 404。以上是当时快照，关注数不代表算法贡献人数；这里只能判断发布入口尚未完成，不能判断未来没有贡献。

维护者必须持续承担题目、独立规则、评审、基准维护和宿主集成。社区可以贡献搜索器、反例、几何修复、对照实验与可视化。开放任务按可独立评审的粒度拆开，先复现并改善一项挑战，再扩大范围。至少安排算法与 PCB 规则两类评审责任；吞吐瓶颈常会转移到验证和评审，不能将这部分工作也隐含交给尚不存在的贡献者。

保持同仓四包，避免过早再拆仓。纯 Go 便于部署和默认 CI，研究者常用的 Python/C++ 可先通过离线文件实验参与；通用跨语言接入仍需单独实现，不能把有 JSON struct 当成已有插件协议。对外发布入口和认领任务是下一步工作，本轮没有执行。具体分工与试点退出条件见[社区启动条件](pcb-solver-community-design-detail.md#社区启动条件与维护分工)。

### 8. 本次验证与尚未验证的结论

实际执行：

```bash
make pcb-solver-test
go list -f '{{.ImportPath}}: {{join .Imports " "}}' ./pkg/pcbmodel ./pkg/pcblayout ./pkg/pcbrouting ./pkg/pcbsolve
go test ./pkg/pcbrouting ./pkg/pcbsolve -run '^$' -bench . -benchmem -benchtime=1x -count=3
```

四包回归通过；依赖符合隔离预期；现有三个 benchmark 各单次运行三遍通过。环境为 darwin/arm64、Apple M1。单次采样区间：绕障约 1.42～1.61ms，小型布局反馈约 0.25～0.55ms，增加 48 个远处器件的案例约 1.06～1.12ms。该设置只用于确认案例可运行，未稳定预热，**不构成性能基线、扩展性证明或外部算法对比**。

文档验证：`make agent-check` 13 项通过，三篇相关文档的 48 个本地链接与 Markdown 锚点检查通过，`git diff --check` 通过。

尚未执行：多层算法实现；新增联合精确参照；完整需求规模基准；外部算法同题比较；社区贡献试点；完整 PCB 路由写入和现场端到端验收。因此本轮结论是“方案有据可行，按条件推进”，不能升级为“多层算法已验证”或“社区交付已保障”。
