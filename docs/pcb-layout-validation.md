# PCB 组合布局开发验证清单

当前目标：**保留已经做好的组内相对布局，以完整电路块为单位调整整板位置，再计算块间
布线通道，必要时反馈让位。** 同网不代表同组；整体移动不是再次打散摆放外围器件。

本页是待办与验收入口，算法调研见 [Layout/Router 研究](pcb-layout-solver-research.md)，
术语见 [概念表](concepts.md#样例参数与事实检查)。公开参数和可照做步骤维护在
[组合移动样例](../.agents/skills/easyeda-agent/references/examples/pcb-group-move/README.md)。

## 场景与测试如何配合

| 资料 | 回答的问题 | 保存什么 |
|---|---|---|
| 开发验证场景 | 用户要的能力在完整操作链上是否成立？ | 来源、起点、完整组、参数、独立要求、步骤、前后结果、未完成项 |
| 自动测试用例 | 改代码后，某条规则是否退化？ | 小输入、断言、正负例、确定的失败诊断 |
| 某次验证记录 | 哪个版本、哪些输入实际跑过？ | commit/工作树差异、输入与候选哈希、命令、报告、图、回读与清理结果 |

先写场景及不变量；为其中缺失能力补失败测试，修实现，运行回归；再按场景离线复现和现场
执行。已有能力先补可迁移的场景和证据，不故意改坏实现制造“红灯”。每轮只推进一个明确
范围；发现问题保留失败输入，修正后重跑该场景，不把 checklist 勾选当执行许可。

## 首项场景卡：LG-01 / LG-02

- **来源**：2026-09-23 用户提出“保留已有相对布局，验证整体器件组合移动”。五成员公开
  合成输入用于独立核对几何，非器件选型/BOM、非真实板测量、非完成态布局标准答案。
- **开始状态**：二层板，U1/C1/C2/R1/D1 已具有不同相对位置和角度；J1/H1 固定；无既有铜。
  U1 footprint anchor 不在 bbox 中心。成员和 pin owner 显式列出。
- **参数**：mil、y 向上、footprint anchor；整体 dx/dy、允许转角、最小净距、成员列表。
  给定偏移是用户要求的移动动作，本例不验证求解器是否会自己找到让位方向。
- **独立验收**：完整成员集合；所有成员相对 anchor 的向量经同一旋转；所有成员间距、
  相对角度、pad 身份/网络保持；非对称 bbox 和 pads 同步；固定对象不在 Apply 中；预览与
  Apply 使用同一候选。0°/90°分别核对，公用模型与宿主适配分别验证。
- **负例**：漏掉 C2 的输入与独立成员表不符；候选只挪 U1；固定 J1 出现在写入集；旋转绕
  bbox 中心；增加未声明铜。不能从已经缩小的 `members` 自证“完整”，成员表必须来自独立
  功能归属。通用“全部业务成员已声明”的自动检查能力也不能凭几何模型声称存在。
- **离线命令与参数**：见[公开场景步骤](../.agents/skills/easyeda-agent/references/examples/pcb-group-move/README.md)。
- **现场步骤（待执行）**：在 ceshi 专用无铜测试组 fresh dump；按实测重绑成员/所有权/PID；
  生成候选；fresh 来源对账；typed Apply；两轮自检与持久化回读。保存原始 DRC 作前后差异，
  不把整板既有错误清零当本场景的几何前提，也不忽略新错误。所有对象按完整数据对账，不能
  只比较计数。最后按 fresh 身份从原参数恢复测试对象，保存重载再核对。
- **证据包**：源码版本与差异、原板、独立成员/固定件/约束、参数、候选、前后图、自动测试
  输出、Apply journal、两轮 fresh 原始回读、逐对象差异、DRC 差异、清理结果。私有现场输入
  留在本地，公开回填可迁移参数与结论。
- **完成条件**：离线几何及 CLI 对账完成，只升级离线复现；上述现场证据完整后才勾选本项。
  内部铜、外部布通和整板布局质量分别由后续场景验收。

## 路线避让开发增量（2026-09-24）

组合移动提供保持组内关系的动作，实际通道占用与冲突反馈决定移动理由。两者配合可实现
路线避让；单看布局无重叠或已有五成员移动例，不能证明路径共同可用。分析发现并修复了
两个会漏解的搜索缺口，并把证据接入以下场景：

| 场景 | 不依赖输出坐标的验收 | 本轮离线结果 |
|---|---|---|
| LG-19 固定布局路线回溯 | 两网分别可达；独立共同路径 witness 合法；求解保持全部固定器件，0 移动/0 新过孔；打乱输入与重命名仍共同通过 | `fixed-route-order` 已通过；修改前原输入失败，仅改 demand ID 就成功 |
| LG-02/09 平移后整组旋转 | 原地旋转碰固定件，单纯平移仍阻挡；允许转角后找到共同路径；组内成员/内部几何同一原始 anchor 投影；禁止旋转时保持失败 | `TestRouteAvoidanceNeedsTranslationThenWholeGroupRotation` 与公共邻域测试已通过 |
| LG-03/07/10 双组递归让位 | 初始机械合法但路由受阻；两个完整组保持相对布局；外部端点随移动重算；三网共同检查，固定物/既有铜/规则保持 | `multi-group-clearance` 已通过；固定第二组、漏外部 demand 负例通过 |

代码输入与期望分别见
[固定布局路线场景](../pkg/pcbsolve/testdata/fixed-route-order/README.md)、
[双组场景](../pkg/pcbsolve/testdata/multi-group-clearance/README.md)。两者都是明确范围的合成
几何，不是 MCU/LDO 真实模块验收。联合路径先在固定布局中回溯，Layout 的反馈邻域再探索
声明平移和旋转，全部尝试共用预算；搜索穷尽当前候选不等于所有物理方案不可行。

整板/局部 SVG 与报告同源，显示真实模型 pads、路径宽度/净距、移动前位置、移动原因和
请求机械禁放区；独立 `render --board --candidate` 缺请求时不能恢复仅在需求中的禁区。
加 `--from request.json` 即可来源对账并显示同一约束。
完整记录与验证结果见 [固定路由回归](../pkg/pcbsolve/testdata/fixed-route-order/README.md)与[跨组间距回归](../pkg/pcbsolve/testdata/multi-group-clearance/README.md)。
