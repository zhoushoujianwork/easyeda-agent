# 高级 CLI 业务验收

本页维护高级 CLI 验收的进入条件和执行要求。当前进度见 [CLI Status](cli-STATUS.md)，
影响验收的问题与覆盖缺口见[已知问题](cli-known-bugs.md#本轮仍缺的验证)。

高级 CLI 用参数和真实工程数据完成选型、规划、求解、Compose/Apply、设计检查、PCB 布局布线
及从需求到成品的闭环。它回答“设计结果是否正确”，与
[基础 CLI 真实链路测试](cli-live-test.md)回答的“单个命令动作是否可靠”分开判定。

## 进入条件

同一安装包、daemon、连接器和测试工程的基础用例 B00–B10 必须全部 `pass`。
基础层仍有 `fail`、`blocked` 或 `not-run` 时，不启动高级 CLI 的现场验收；
已有求解或 DRC 回包只作为历史观察，不能补签基础门禁，也不能称高级验收通过。

以上为默认规则。[v1.8.0 已获用户明确的范围例外](releases/release-1.8.md#已接受的已知限制)：
#55、#260、#261 不再整体阻断，可结合已有基础检查、定向复测及当前目标/完整基线核对进入高级用例。
不要求先修三项，也不只因这三项重跑基础全集；具体调用仍如实失败退出，严格基础结论和其他缺陷的判据保留。

## 执行范围与证据

2026-09-25 用户决定 [v1.7.0](releases/release-1.7.md)只验收基础 CLI，高级 A00–A06
留到下一版本；该发布材料中的 `not-run` 保留，不作为后续版本默认豁免。

2026-09-26 续测已确认复用基础测试工程及叠层 A；设计输入、测量中断和恢复经过见
[续测记录](reviews/2026-09-26-advanced-cli.md)，相关修复见[历史证据索引](reviews/README.md)。
这些已确认的输入继续保留；恢复时按本页准入范围核对证据，不以故障恢复补签原失败。

满足本轮准入条件后，按[高级用例与前置条件](cli-advanced-test-detail.md)检查：
原理图数据驱动选型与布局、保护 Apply、严格质量门；PCB 同步、规则、布局、用户确认、
布线与铜、保存重载和独立复核。完整端到端只把
[`esp32MiniRequire.md` 第一节](../esp32MiniRequire.md)的客户原始需求交给执行 Agent，
按[现行验收标准](e2e-automation-acceptance.md)及公开 Skill 的 S0–S6/P0–P10 流程执行。

高级结论按每个设计事实给出 `pass`、`fail`、`blocked` 或 `not-run`，保留输入哈希、
候选报告、Apply journal、DRC 和 save→reload→fresh readback。离线候选、单页 gate
或截图均不等于完整设计通过。
